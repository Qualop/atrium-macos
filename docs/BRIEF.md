# Atrium 인계 문서

이 문서는 Atrium을 왜, 무엇을 만드는지와 지금 유효한 결정, 사용성 원칙, 먼저 확인할 위험을 새 세션에 넘긴다. 2026-10-29 데스크톱 앱 세션에서 처음 썼고, 지금은 P8(v0.7, 가지 펼치기)까지 만든 상태의 결정을 담는다. 단계별로 만든 것은 저장소 `README.md`의 변경 이력, 지금의 구조는 `docs/ARCH.md`, 할 일과 열린 결정은 `docs/PLAN.md`, 결정의 경위는 `docs/decisions.md`에 있다. 세부 근거는 `docs/research/`에 있다.

## 1. 왜 만드는가

AI가 작업의 0→90%를 대신 하게 되면서 일을 파이프라인처럼 겹쳐 돌릴 수 있게 됐다. 한 작업의 처리 속도는 그대로지만 처리량은 늘었다. 그러나 90→100%를 마무리하는 단계는 여전히 사람이 하고, 이 단계는 하나뿐이다. 여러 작업을 오가다 보면 각 작업의 맥락을 잊는 일이 잦다.

2026-10-29 기준으로 최근 7일 동안 Claude Code 대화 기록이 452개 쌓였다. 데스크톱 앱에서 보관하지 않은 세션 목록 상위 40개는 모두 최근 사흘(10/27~10/29) 안에 활동했고, 그중 19개는 한 실험 세션이 띄운 하위 세션이었다. 앱의 사이드바는 최근 활동 순으로 계속 순서가 바뀌는 목록이라 "어디에 뒀는지"로 기억할 수 없다.

Atrium은 이 문제를 푼다. 목표는 세 가지다.

1. **시각화:** 여러 에이전트 세션과 그 상태를 한 판(무한 캔버스)에 늘어놓고, 둔 자리를 지킨다. 사용자가 연 모든 CLI 세션(에이전트와 일반 셸)을 워크스페이스(리포지토리)와 상관없이 캔버스 하나에 놓고, 세션 사이의 관계를 선이나 붙여 묶기로 보여준다. 전체를 한눈에 보며 어떤 질문과 요청이 있는지 찾고, 어느 세션이든 캔버스에서 바로 들어간다. 불러야 보이는 목록이 아니라 늘 보이는 오버뷰다(2026-10-30, 같은 날 워크스페이스별 판에서 단일 캔버스로 바꿈).
2. **판에서 바로 말 걸기:** 판 위의 세션에 메시지를 바로 보낸다.
3. **세션끼리 연결:** 한 세션이 다른 세션(herdr 패널, 예: `w2:p1`)에게 일을 시키고 그 관계를 오래 이어 가게 한다. 판은 누가 누구에게 무엇을 시켰는지 선으로 보여준다(2026-10-30 추가). 사람이 세션 하나에게 "워커를 만들어 나눠 맡겨"라고만 지시하면, 그 세션이 정해진 방법으로 하위 세션을 띄우고 herdr로 이어 일을 나누며, 하위 세션도 같은 방법으로 다시 펼친다. 판에는 그 모양이 나무처럼 보인다(2026-10-31 추가, P8).

## 2. 무엇을 만드는가

symvibe(macOS 전용 유료 앱)의 화면 구성, 사용 흐름, 생김새를 Windows와 Claude Code CLI로 옮긴다. symvibe의 판 위 콘솔은 진짜 터미널이고, 명령을 보낼 때는 글을 콘솔에 붙여 넣은 뒤 Enter를 대신 누른다. 판에서 세션에 말을 걸 수 있는 이유는 판 쪽이 터미널을 띄우고 쥐고 있기 때문이다. Atrium에서는 herdr가 터미널을 쥐고, 판은 herdr API로 세션을 띄우고 글을 보낸다.

symvibe 해부 내용은 `docs/research/symvibe.md`에 있다.

**2026-10-30에 정한 방향.** 사용자는 장기적으로 작업 환경을 CLI로 모두 옮긴다. 그래서 판은 데스크톱 앱 세션과 판 밖의 herdr 세션을 보여주지 않는다. 대신 판 전용 herdr 세션 안의 세션들을 서로 잇는 데 집중한다.

- 일을 나누고 시키는 것은 세션(에이전트) 자신이 herdr 스킬(`~/.agents/skills/herdr/SKILL.md`)로 한다. herdr 패널 안의 에이전트는 `herdr agent prompt <이름|w2:p1> "…" --wait`로 다른 에이전트에게 일을 시키고, `herdr pane split`과 `herdr agent start`로 새 에이전트를 띄운다.
- 워크트리를 파서 따로 개발하는 것 같은 작업 방식은 각 하네스(Claude Code, Codex, Hermes 등)의 규칙을 그대로 따른다. 판은 워크트리를 직접 만들거나 규칙을 정하지 않는다.
- 판이 하는 일은 세 가지다. 세션을 띄운다. 세션끼리 연결해 준다(누가 누구의 무슨 역할인지 알려 준다). 그 연결과 오가는 일을 판 위에 선으로 보여준다.

## 3. 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 플랫폼 | Windows 구현을 유지하며 macOS 포팅을 추가한다(2026-11-02). macOS는 Unix 소켓, Application Support 데이터 폴더, POSIX 프로세스 조회를 쓴다. Apple Silicon에서 검증하며 Intel은 미검증이다. | 사용자의 Mac 실행 요청. 기존 herdr 0.9.5 프로토콜과 판 데이터 모델을 유지한다. |
| 이름 | `Atrium`. 명령어, 환경 변수 접두어, 데이터 폴더, herdr 세션 이름은 `atrium`(`ATRIUM_*`)이다. 옛 이름 `multitask`·`mtask`·`MTASK_*`도 당분간 받고, 옛 이름의 판 기록과 세션은 처음 켤 때 옮긴다. 저장소 폴더는 그대로다(2026-11-01 사용자 요청, P18). | `mt`는 Windows SDK의 `mt.exe`와 겹칠 수 있다. |
| 엔진 | Claude Code CLI 세션은 herdr 패널에서 돈다. 판은 herdr API로 세션을 띄우고, 상태를 받고, 글을 보낸다(2026-10-29 결정). | 데스크톱 앱은 앱 밖에서 세션에 입력을 넣는 통로를 열어 주지 않는다. herdr는 터미널 소유, 화면과 무관한 세션 유지, 재시작 때 `claude --resume`을 이미 한다. E0에서 세션 시작, 상태, 화면, 글 보내기를 모두 확인했다(`docs/experiments/E0.md`). |
| 방향 | 판은 세션을 띄우고, 세션끼리 연결해 주고, 그 연결을 보여준다. 일을 나누고 시키는 것은 에이전트가 herdr 스킬로 직접 하고, 워크트리 같은 작업 방식은 각 하네스의 규칙을 따른다(2026-10-30 결정). | 사용자는 장기적으로 CLI로 옮긴다. 하네스(Claude Code, Codex, Hermes 등)가 이미 작업 규칙을 가지고 있으므로, 판이 같은 일을 다시 만들지 않는다. |
| 에이전트 종류 | herdr가 지원하는 CLI를 실행한다. Claude Code와 Gemini CLI는 상세 hook, Google 개인 계정은 Antigravity(agy)를 쓴다. Gemini CLI는 설치된 모델 목록, agy는 인증된 CLI 목록을 조회한다. 다른 종류는 herdr 상태를 사용한다(2026-11-03). | 승인·로그인·초기 동의 화면은 사람이 처리한다. Gemini CLI 개인 OAuth는 서비스에서 거절될 수 있다. |
| 워크스페이스 | 리포지토리 하나를 워크스페이스 하나로 본다. 키는 시작 폴더의 git 공통 폴더(`--git-common-dir`)라서 워크트리는 본 저장소와 같고, git이 아닌 폴더는 그 폴더다. 살아 있는 워크트리는 본 저장소 영역 옆의 작은 영역으로 따로 보이고 브랜치 화살표로 잇는다(2026-11-02 사용자 요청, P27). 세션이 다른 저장소로 `cd`해도 옮기지 않고 표시만 한다. 판 전용 herdr 세션 안의 세션만 담는다. 워크스페이스는 단일 캔버스 위의 영역이다. 코드에서는 `workspaceKey`, herdr 작업 공간은 `herdrWorkspaceId`다(2026-10-30, P5·P6). | 세션은 모두 어떤 리포지토리에 묶여 있다. 워크스페이스별 탭이나 판을 오가면 관계와 전체가 한눈에 보이지 않는다(사용자). 자리는 사람이 정하고 시스템은 지킨다(4절). |
| 일반 셸 | 판 전용 herdr 세션에 열린 에이전트 없는 패널(PowerShell)도 세션으로 보여준다. 셸에서 에이전트가 시작되면 같은 노드의 종류만 바뀌고, 판이 띄우지 않은 에이전트가 끝나면 같은 노드가 셸로 돌아간다. 셸에는 명령 바로 글을 보내지 않는다(5절 전달 규칙). 터미널 입력과 끄기는 된다. 셸이 쉬는지 명령을 돌리는지는 화면 끝 줄이 프롬프트인지로, 명령 이름은 셸 PID의 자식 프로세스로 본다(2026-10-30 결정, P5). | 워크스페이스에 열린 CLI 세션을 빠짐없이 보여주기 위해서다. herdr는 패널 생성·종료 이벤트를 준다. Windows에서 herdr `pane.process_info`는 셸 자신만 주고 셸 아래 명령은 주지 않는다(P5). |
| herdr 스킬 | 판이 띄우는 claude마다 herdr 스킬 플러그인을 `--plugin-dir`로 넘긴다. 스킬 글은 고정한 herdr의 `herdr --skill` 출력이다. 짧은 안내(`--append-system-prompt-file`)로 판의 연결 알림을 알아듣게 하고, herdr 명령에 `--session`·`--machine`·`--remote`를 붙이지 않게 한다(P4). | Claude Code는 `~/.agents/skills`를 읽지 않는다. 사용자 설정과 `~/.agents/skills`는 고치지 않는다. 패널의 `herdr` 명령은 herdr가 넣는 `HERDR_SESSION`·`HERDR_SOCKET_PATH`로 판 전용 세션에 붙는다. |
| 알아채기 | Claude Code, Gemini CLI, Antigravity의 셸 hook으로 에이전트 간 요청을 추적한다. 받는 쪽 상태는 herdr로 본다. Gemini 완료 본문은 hook으로, Antigravity는 해당 대화 기록에서 가져온다(2026-11-03). | Antigravity hook은 완료 본문·셸 stdout을 제공하지 않는다. 없는 출력은 만들지 않는다. |
| 연결 | 순서 있는 두 세션 쌍마다 연결 하나를 SQLite에 둔다. 판에서 A → B를 이으면 A에게 B의 herdr 이름, 패널, 역할을 알린다. 끊으면 끊겼다고 알리고, B의 패널 ID가 바뀌면 새 패널을 알린다. 오간 기록은 끊어도 남는다(P4). | 일을 시키는 것은 A가 herdr 스킬로 한다. 판은 누가 누구의 무슨 역할인지만 알려 준다. |
| 가지 펼치기 | 협업 설정이 연결된 판 세션은 `atrium child`로 하위 세션을 만든다. 기본 종류와 같은 제공자의 모델을 상속하고, 종류를 바꾸면 다른 제공자의 모델을 상속하지 않는다. 역할 선과 부모 오른쪽 배치를 유지한다. 하위 개수·깊이·전체 상한과 자기 자손만 끄는 규칙을 지킨다(2026-11-03). | Gemini·Antigravity도 팀을 구성한다. CLI별 승인 정책은 그대로 적용하며 동일 사용자 계정 내 협업이다. |
| 판에 올린 에이전트 | 판 전용 herdr 세션에 판이 모르는 에이전트가 나타나면 판에 올리고, 띄운 세션(hook의 `agent start` 명령, 없으면 같은 작업 공간의 판 세션)과 잇는다. hook이 없으므로 다른 종류처럼 다룬다. 같은 작업 공간에 다른 패널이 있으면 끌 때 그 패널만 닫는다(P4). | 에이전트가 띄운 에이전트는 판의 설정(hook, 스킬, 권한 모드)을 받지 않고 그 하네스의 사용자 설정을 따른다. 작업 공간째로 닫으면 띄운 쪽까지 닫힌다. |
| 기술 구성 | Electron, React, `@xyflow/react`, xterm.js, SQLite(Node 24 내장 `node:sqlite`, E8). 터미널은 herdr 0.9.5(버전 고정). 백엔드는 Node 24 JavaScript(ESM)이고 의존성은 `ws` 하나다(P1). 창은 Electron 45, React 19, `@xyflow/react` 12, xterm.js 6(WebGL, unicode11), esbuild이고 백엔드 WebSocket에 직접 붙는다(P2). | node-pty는 쓰지 않는다. herdr가 ConPTY를 맡는다. `node:sqlite`는 설치할 것이 없고 기능과 속도에서 잃는 것이 없다. 실험 단계 모듈이라 저장소 모듈 안에 가둔다. |
| 화면 구조 | 주 화면은 symvibe와 같은 무한 캔버스 **하나**다. 모든 워크스페이스의 세션이 한 캔버스에 있고 워크스페이스는 그 뒤의 영역이다. 아래쪽 워크스페이스 단추와 검색으로 바로 가고, 멀리서도 노드마다 기다리는 질문과 마지막 요청이 읽힌다. 노드는 줌에 따라 터미널, 대화 보기, 요약으로 바뀐다. 탭, 분할 창, 목록을 주 탐색으로 쓰지 않는다(사이드바는 평소에 닫힌 보조 목록)(2026-10-30, P6). | 탭과 목록은 한 번에 하나만 크게 보여서 무엇이 돌고 있는지 숨긴다(Orca, Ovis 방식). 워크스페이스별 판도 같다. 세부는 `docs/ARCH.md` 4절 H와 7절 |
| 화면 모양 | 판의 생김새는 symvibe 데모 화면을 모사한다: 따뜻한 검정 캔버스와 점 격자, 위 막대 없이 떠 있는 알약 크롬과 도구 레일, 진짜 터미널 콘솔(머리에 종류 아이콘, 이름, 상태 알약). 강조색은 Atrium 로고의 초록이고 내 차례만 주황이다(2026-11-01). 기준은 HTML 목업 `app/design/board-mock/`이다. 이름, 로고, 에셋(그림, 영상, 글꼴 파일), 코드는 가져오지 않는다(2026-10-31). | 화면이 읽기 어렵고 못생겼다(사용자). AI 이미지 시안은 어색했고, 실제 화면을 재서 따라 그린 목업이 가장 가까웠다(`docs/research/board-mock.md`). |
| 화면 언어 | 화면 글은 영어와 한국어를 고를 수 있고 기본은 영어다. 에이전트에게 보내는 글과 문서는 바꾸지 않는다(2026-11-01 사용자 요청, P16). | 사용자가 아래 바를 symvibe 데모처럼 영어로 보기를 원했다. |

## 4. 사용성 원칙

여러 차례 논의에서 정리한 원칙이다. symvibe가 이미 하는 것과 Atrium에서 바꿀 것을 함께 적었다.

- **자리는 사람이 정하고, 시스템은 그 자리를 지킨다.** 상태가 바뀌어도 노드는 움직이지 않고 색과 표시만 바뀐다. 사람은 둔 자리로 작업을 기억한다. 새 콘솔은 빈자리에 놓고, 다른 노드 위에 겹치지 않는다(symvibe와 같다).
- **"내 차례"는 노드를 옮기지 않고 가리킨다.** 위쪽에 내 답이 필요한 세션을 모아 보여주고, `N`을 누르면 그 자리로 이동한다(symvibe의 needs you 칩과 같다).
- **"내 차례"는 모든 프로젝트를 가로질러 보여준다.** symvibe는 보드 단위로 보여준다. 사용자는 여러 프로젝트를 동시에 오가므로 홈 화면에서 전체를 볼 수 있어야 한다. 내 차례 칩은 모든 워크스페이스를 가로지르고, 누르면 그 노드로 간다.
- **연 세션은 모두 처음부터 한 캔버스에 보인다.** 세션을 목록에서 골라 불러오는 방식이 아니다. 전체를 줄여 보아도 어떤 세션이 무엇을 묻고 무엇을 요청받았는지 읽히고, 누르면 바로 그 세션에 들어간다(P5에서 시작, P6에서 단일 캔버스로).
- **들어갈 때 브리핑.** 오래 손대지 않은 세션으로 돌아오면 마지막으로 내가 한 말, AI가 한 일, 지금 필요한 것을 먼저 보여준다.
- **검토 대기를 따로 센다.** AI가 끝냈지만 사람이 아직 보지 않은 상태가 90→100 단계의 대기열이다. OpenCove의 작업 상태 `todo / doing / ai_done / done` 중 `ai_done`이 이 상태다.
- **판 정리가 또 하나의 일이 되지 않게 한다.** 자유 배치는 노드와 덩어리 단위로 하고, 쉬는 세션은 흐리게, 닫은 세션은 판에서 빼서 보관함에 둔다. 이 항목은 제안이며 v0.2 이후에 다듬는다.
- **마지막 Enter는 사람이 누른다.** 콘솔 종료, 재시작, 사람이 시키지 않은 단계는 확인을 받는다(symvibe와 같다).

## 5. v0.1 범위

가장 위험한 부분을 먼저 확인하는 최소 버전이다. 기능별 동작과 모듈은 `docs/ARCH.md`, 단계별 범위와 완료 기준은 `docs/log/`에 있다. 이 절의 v0.1은 P2(`docs/log/p2-window.md`)다.

**만들 것**

1. Electron 창 하나에 판(무한 캔버스) 하나
2. 콘솔 노드 4개. 각 콘솔은 herdr 패널에서 `claude`를 띄우고, herdr 제어기(`terminal session control`)가 주는 화면 프레임을 xterm.js로 그린다.
3. hook으로 받은 상태 필: starting, ready, working, waiting(내 답 필요), error, exited(정의는 `docs/ARCH.md` 3절)
4. "내 차례" 칩과 `N` 이동
5. 아래쪽 명령 바. `@이름 내용`을 보내면 herdr `agent.prompt`로 그 콘솔에 글과 Enter를 넣는다. 여러 줄, 100KB까지 한 턴으로 들어간다(E3).

**명령 전달 규칙(symvibe에서 가져온다)**

- 에이전트가 돌고 있는 콘솔에만 보낸다. 일반 셸에는 보내지 않는다.
- 콘솔이 waiting 상태면 보내지 않고 기다린다. herdr의 `agent.prompt`는 막힌 패널에 보내면 거부하므로, 판은 대기열에 두었다가 다시 보낸다.
- 글은 괄호 붙여넣기로 감싸 한 번에 넣고 Enter를 보낸다. `agent.prompt`가 이렇게 한다. 감싸지 않은 여러 줄은 줄마다 따로 제출된다(E4).

**완료 기준(제안)**

- 콘솔 4개에서 `claude`가 돌고, 권한 요청이 뜨면 해당 상태 필이 waiting으로 바뀐다.
- 명령 바에서 `@이름`으로 보낸 문장이 그 콘솔에 들어가 실행된다.
- 아래 위험 1, 2의 확인 결과가 기록된다.

**결과:** 2026-10-29에 P2로 이 범위를 끝냈다. 그 뒤 단계별로 한 것은 저장소 `README.md`의 변경 이력, 다음 후보와 열린 결정은 `docs/PLAN.md`에 있다.

## 6. 먼저 확인할 위험

1. **한글 입력:** xterm.js 안의 Claude Code 입력칸에서 한글 조합이 제대로 되는지 확인해야 한다. 문제가 있어도 명령 바는 일반 입력칸이라 우회할 수 있다. E6에서 CDP 조합 이벤트로 흉내 낸 부분은 모두 됐다(조합 중 보내지 않음, 음절마다 한 번, 배율과 무관). 실제 IME 창, 한/영 전환, 조합 중 Enter는 사람이 점검표(`docs/experiments/E6.md` 4절)로 확인한다.
2. **콘솔이 많을 때:** Chromium은 한 화면에서 동시에 유지하는 WebGL 컨텍스트 수에 한도가 있어서, 넘으면 오래된 것부터 잃는다. OpenCove는 WebGL로 그리는 터미널을 기본 8개로 제한하고 나머지는 DOM으로 그린다. 판을 많이 축소하면 실제 터미널 대신 상태와 마지막 몇 줄만 보여주는 방식도 함께 쓴다(제안). herdr 구조에서는 가까이 보이는 노드마다 제어기 프로세스(`herdr.exe`, 약 17MB)가 하나씩 붙으므로, 그런 노드 수에도 상한을 둔다. E5에서 8개를 붙여 보니 제어기 합계 127MB, 창 약 420MB였고 50ms를 넘는 화면 프레임은 없었다. WebGL 예산 8과 제어기 상한 8을 기본값으로 정했다. DOM 대체는 동작하지만 같은 부하에서 창 CPU가 약 3배라, 컨텍스트를 잃었을 때만 쓴다. E5에서 한 번 컨텍스트를 잃은 뒤 모든 터미널이 놓였는데, P3에서 58번 다시 해도 나지 않았다. 노드마다 오류 경계와 얼굴 경계 이력(16px)을 넣었다.
3. **데스크톱 세션을 CLI로 이어 가기:** 아직 해 보지 않았다. 기존 세션으로는 시험하지 않으므로(3절 "실험") v0.1 범위에서 뺀다. 시험이 필요해지면 사용자에게 시험용 세션을 따로 받는다.

추가로, Claude Code 세션 하나는 프로세스 하나다. 2026-10-27 Radar 세션의 측정에서는 데스크톱 앱의 Claude Code 프로세스 36개가 메모리를 약 9.9GB 썼다. 판에서도 콘솔을 일시정지하거나 닫는 동작이 필요하다. 2026-10-29에는 `claude.exe` 프로세스가 44개 돌고 있었다. 데스크톱 앱 세션도 같은 이름의 프로세스이므로, 시험 뒤에는 직접 띄운 프로세스만 PID로 끈다.
