# Atrium 계획

## 지금: v0.3 통합의 최종 확인

승인 범위는 원본 P30~P55의 실행 프리셋·실제 모델 목록·신뢰 관문, 보드 배치와 탐색, Claude/Codex 대화 사본, 다중 클라이언트·웹·Tailscale이다. macOS·Node 지원, 제공자별 복구, 기존 worker 상한과 원본 보호를 유지한다. 워커 상한 제거와 미통합 P56~P59는 제외한다. 현재 구조는 ARCH 1~7절을 따른다.

- 최종 변경 집합에서 백엔드·화면·Node 조합별 검증 증거를 모으고 재현 조건을 남긴다. 구현·자동 시험·실기기 검증·배포 상태를 따로 판단한다.
- 호출자 기본값·즐겨찾기 이행, 실제 모델 목록, 인자 경계, 비밀 값 비노출을 확인한다. 새 보드의 Gemini는 하나이고 기존 DeepSeek 즐겨찾기는 유지한다.
- 명령 프리셋의 원문과 env는 분리한다. 다시 열기에서도 비공개 `launcherCommand`·`launcherEnv`를 써야 하며, 공개 이벤트의 가림 문자열을 실행하면 안 된다.
- 데스크톱 가져오기는 기본 선택 없음, 명시적 항목만 복사, 원본 불변성, 실패 정리를 확인한다. Codex는 native 사본 UUID로만 깨우고 자동 절전 대상을 Codex 전체로 넓히지 않는다.
- 동시 세션 생성 예약, 자손 정리, 신뢰 관문 시간 초과, 패널 소유권, 공유 제어기 연결 세대 검사를 확인한다.
- 원격 기본 꺼짐, 호스트의 명시적 활성화, 기기 등록·회수, Tailscale 정책, 재접속 동작을 확인한다. 실제 Tailscale 설정 변경은 별도 승인 없이 실행하지 않는다.
- 최종 앱 패키지에서 상대 번들 경로, 받는 Mac의 CLI 탐색, 의존성·글꼴 라이선스를 확인한다. 기존 설치 앱과 소스의 버전 차이를 구분한다.

완료 기준: 승인 기능과 보존 조건의 증거가 최종 변경 집합에 대응하고, 남은 문제와 실기기 확인 범위가 명시되어 있으며 지휘 세션이 최종 판단을 기록한다. 이 PLAN은 시험 통과나 배포 승인을 대신하지 않는다.

## 다음: v0.3 배포와 실제 사용 피드백

목표:

- 최종 승인된 소스로 대상 CPU의 배포 파일을 만들고 버전·서명·라이선스·설치 경로를 확인한다.
- 사용자 데이터와 기존 세션을 보존하는 설치·업데이트 절차를 정리한다.
- 보드와 원격 브라우저 사용 피드백을 재현 가능한 작은 작업으로 나눈다.

완료 기준: 배포 파일과 검증 증거가 같은 변경 집합을 가리키고, 승인된 배포 경로 및 알려진 제한을 공개 문서에 반영한다. 게시 전에는 릴리스 링크를 제작·게시 증거로 취급하지 않는다.

## 열린 결정

- `herdr agent prompt|wait|read` 자동 승인 범위를 자기 자손으로 좁힐지. 현재는 같은 사용자 보드의 다른 에이전트에도 접근한다.
- 워커 상한을 변경할 필요가 있는지. 현재 기본은 직접 자식 4개·깊이 3단계·전체 하위 16개이며, 자동 제거하지 않는다.
- 일반 사용자에게 원격 접속을 어느 범위까지 권할지. 등록 기기는 호스트의 터미널 권한을 가지며, 미통합 P56~P59 제안은 별도 검토 대상이다.
- 판 밖에서 채택한 제공자 세션에 관리 설정을 연결할지. 출처와 정확한 대화 ID가 없는 세션을 자동 복구 대상으로 확대하지 않는다.
- 검색을 보드 색인 밖의 전체 대화 기록까지 넓힐지, 루프의 종료 판정을 답의 글자 일치 밖으로 넓힐지.
- 실제 사용 결과에 따라 전역 `@all` 외의 프로젝트별 보내기, 연결선·도킹 배치와 터미널 연결 예산을 더 조정할지.
