# Atrium 계획

## 지금: 0.4 통합과 설치 앱 검증

원본 P111까지의 기능을 Mac 분기에 통합하고 제공자별 native 기록·식별자·권한 정책과 기존 사용자 데이터를 보존한다. 구조와 API는 ARCH 1~7절을 따른다. 소스 반영과 최종 검증·배포는 구분한다.

- 새 임시 프로필·합성 대화로 회귀 시험을 실행한다. 원본 대화·기존 세션을 재개·분기·종료·보관하거나 신뢰를 대신 수락하지 않는다.
- 부모 권한 변환과 관리 제공자 실행·재개·깨우기의 도구 자동 옵션을 확인한다. 공개 `agentAutoApprove` 기본 false를 유지하고, 사용자에게 허용받은 설치 보드만 별도로 켠다. 로그인·신뢰·질문은 사람이 처리한다.
- PC 응답 필요 안내와 native OS 알림을 눌렀을 때 해당 실제 터미널이 열리고, 연결 교체·IME 입력 중 오래된 응답이 입력을 바꾸지 않는지 확인한다.
- 폴더 자동 그룹·혼합 워크트리 도킹·관계별 정리·되돌리기, 개별/프로젝트 절전과 미사용 사본 제외를 검증한다.
- 쿠키·선택적 패스키·기기 회수·휴대폰·푸시를 격리 환경에서 확인한다. 원격 기본 꺼짐과 실제 Tailscale·전역 설정·데이터 공유 동의 상태를 유지한다.
- Node 지원 범위와 Mac native 라이브러리·CPU·서명·실행 경로를 확인한다. 소유자 저장소의 stable/dev 앱 번들 업데이트·백업 복구와 설치본 재실행을 점검한다.

완료 기준: 남은 통합·native 실행 환경·패키징 검사를 통과하고 실제 검증 범위와 한계를 구분해 기록한다. 릴리스 파일·체크섬·직접 링크는 지휘 세션이 확정한다. 부분 시험 수를 최종 통과로 쓰지 않는다.

## 다음: 설치본과 원격 기기의 실사용 점검

목표:

- 사용자가 고른 기기에서 로그인·재연결·알림 클릭·절전 복귀를 확인한다.
- 긴 협업 작업과 재시작에서 정확한 native ID·비공개 실행 값·닫힌 기록을 점검한다.
- 실사용 근거가 있는 화면·자원 문제만 분리해 개선한다.

완료 기준: 실기기 재현 조건과 수정 범위가 있으며 워커 상한·기존 데이터·명시적 원격 허용을 유지한 검증 결과가 있다.

## 열린 결정

- 판 밖에서 채택한 제공자에 관리 설정을 연결할지. 출처와 정확한 대화 ID가 없는 세션의 자동 복구는 확대하지 않는다.
- 검색을 보드 색인 밖으로 넓힐지, 루프 종료 판정을 답의 글자 일치 밖으로 넓힐지.
- 실사용 결과에 따라 터미널 연결 예산·원격 알림 표현과 프로젝트별 전송 동선을 더 조정할지.
