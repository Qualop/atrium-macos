## 옮김: 2026-10-29 통신 속도 측정과 해석(옛 PLAN 2절)

#### 2.1 측정(2026-10-29, 이 PC)

| 측정 | 결과 | 출처 |
|---|---|---|
| 지속 연결(TCP, 127.0.0.1) 왕복, 200바이트, 2,000회 | 중앙값 0.036ms, p99 0.129ms | 이 문서 작성 때 |

#### 2.2 해석

- **통신은 병목이 아니다.** 가장 느린 herdr 요청도 화면 한 프레임(약 16ms)의 수십분의 1이다. herdr는 요청마다 연결을 새로 열지만 0.37ms라 문제가 되지 않는다. 다만 짧은 시간에 수천 번 부르는 설계는 피한다.
- **hook은 http 방식으로 받는다.** Claude Code는 hook이 응답할 때까지 기다린다(E2에서 1.5초 늦게 응답하자 도구도 1.5초 멈췄다). command hook을 PowerShell로 돌리면 이벤트마다 약 0.2초가 붙는다. http hook은 프로세스를 띄우지 않는다. 수신기는 토큰을 확인하고 먼저 200으로 응답한 뒤 처리한다. 설정 파일의 hook 시간 제한은 2초로 둔다.
- **화면은 보이는 노드에만 보낸다.** 쉬는 Claude Code 세션은 출력이 없고, 한 턴의 프레임도 2.7~31KB였다(E0 3.3). 그래도 노드마다 제어기 프로세스가 하나씩 붙으므로(약 17MB), 가까이 보이는 노드에만 붙인다.
- **화면 글자를 긁어 상태를 정하지 않는다.** 상태는 herdr 상태와 hook으로, 내용(마지막 답, 지시, 도구 사용)은 hook 입력과 대화 기록으로 얻는다. 화면 읽기(`pane.read`)는 요약 얼굴, 시작 대화상자 확인, 권한 요청 선택지 읽기(4절 A1)에만 쓴다.

## 옮김: 2026-10-29 herdr 클라이언트로 정한 경위(옛 PLAN 10절)

- herdr가 주지 않는 것: 무엇을 묻는지, 마지막 답, 오류 종류. 소켓 API의 출력 스트림(`pane_output_changed`는 구독할 수 없다)
- 위험과 대책
  - 화면 스트림이 공개 소켓 API가 아니라 CLI 보조 통로다 → 버전을 고정하고, 어댑터 안에 가둔다.
  - 상태가 화면 판정이라 모르는 대화상자를 `idle`로 볼 수 있다 → hook과 합치고 어긋나면 추정 표시
  - 패널 크기를 herdr 화면과 제어기가 다툴 수 있다 → 판 전용 세션을 쓰고, 다른 클라이언트가 붙으면 경고(D3)
  - 소켓 API의 호환 약속이 문서에 없다 → 붙을 때 `ping`의 `protocol`과 `capabilities` 확인
  - 서버가 환경 변수를 물려준다 → 판이 깨끗한 환경으로 서버를 띄운다
  - 제어기 프레임은 herdr가 다시 그린 화면이라 터미널 모드가 클라이언트에 오지 않는다(E4) → 판이 붙여넣기 감싸기와 휠 변환을 한다(9.2). herdr를 올릴 때 이 동작이 바뀌는지 어댑터 시험에 넣는다.
  - 기본 이어 가기는 `claude --resume <ID>`만 실행해 판의 실행 인자를 버린다(E7) → 시작할 때 `resume_argv`를 등록한다(4절 B3)
  - 구독할 패널 목록을 바꾸는 사이에 이벤트를 잃을 수 있다. 세션을 잇달아 띄우면 `agent_detected`가 사라졌다(P2) → 옛 구독을 잠깐 겹쳐 열고, 끝난 적 없는 세션에 상태 이벤트가 오면 claude가 있다고 보는 안전망을 둔다(5절 herdr 어댑터)
  - WebGL 컨텍스트를 일부러 잃게 한 네 번 중 한 번은 모든 터미널이 놓였다(E5 2.5). P3에서 58번 다시 잃게 했지만 다시 나지 않아 원인은 못 찾았다. 가장 유력한 후보는 그 시험이 얼굴 경계(360px)에 딱 걸려 배율이 조금만 바뀌어도 8개가 함께 놓인 것이다 → 노드마다 오류 경계, 얼굴 경계 이력 16px, 조사용 기록(`mt.trace=1`)을 넣었다(`docs/P3.md` 3.3)
  - herdr는 `session.json`을 띄엄띄엄 저장해서, 띄운 지 얼마 안 된 세션은 서버가 죽으면 작업 공간째로 잃는다(P3) → 판이 되살린다(4절 C3)
- 앞서 검토한 직접 백엔드 구조(node-pty로 터미널을 직접 쥐는 방식)는 E1·E2로 동작을 확인해 두었다. herdr를 떠나야 할 때 대안이다. OpenCove 코드 지도(`docs/research/opencove.md`)의 hook 판정과 입력 처리도 그때 다시 참고한다.

## 옮김: 기능 시나리오(옛 PLAN 4절, 2026-10-29~31)

처음 정한 시나리오와 단계마다 만들며 정한 것이다. 지금의 동작을 줄인 것은 `docs/ARCH.md` 4절에 같은 번호로 있다. 시나리오 안의 "단계: …" 줄은 그 기능을 만든 단계다.

각 시나리오에 보여줄 것, 백엔드가 준비할 것, 단계를 적었다.

### A. 알아차리기

**A1. 내 답이 필요하다(권한 요청, 질문)**
- 보여줄 것: 세션 이름, 프로젝트, 묻는 내용(권한이면 도구 이름과 명령 또는 파일, 질문이면 질문 글과 선택지), 기다린 시간, 그 세션으로 가는 길. 여러 개면 오래 기다린 순서로 모든 작업 공간을 합쳐 보여준다.
- 백엔드: herdr `blocked` 이벤트로 waiting을 정하고, hook(`PermissionRequest`, `PreToolUse`)의 `tool_name`, `tool_input` 요약, 질문과 선택지를 붙인다. waiting이 시작된 시각을 기록하고, OS 알림 이벤트를 낸다.
- OS 알림(P3): waiting이나 trust_wait가 되면 1.2초 기다렸다가 정한다(hook이 herdr보다 먼저 오는 틈과 바로 풀리는 요청을 거른다). 창에 초점이 있고 그 노드가 보이면(노드 절반 이상이 판 안, 화면 너비 200px 이상) 띄우지 않고, 그 대기도 알린 것으로 친다. 같은 대기(`tool_use_id`, 없으면 시작 시각)에는 한 번만 띄운다. 누르면 창이 앞으로 오고 그 노드로 간다. 창을 닫으면 앱이 끝나므로 알림도 없다(트레이 상주는 8절).
- 카드의 선택지 출처: 질문은 hook(`PreToolUse(AskUserQuestion)`의 `tool_input.questions`)으로 그린다. 권한 요청은 선택지 수와 문구가 도구마다 다르고(Write 3개, Bash 4개, PowerShell 2개) `PermissionRequest`의 `permission_suggestions`와도 다르므로 화면(`pane.read { source: "detection" }`)에서 읽는다(E9).
- 답하기: 승인 카드에서 `agent.send_keys`로 답한다(P2). 모든 선택지에 답할 수 있음을 E9에서 확인했다. 커서 위치에 기대지 않도록 숫자 키를 기본으로 쓴다.

  | 카드 | 키 |
  |---|---|
  | 권한 승인 | `1` |
  | 권한의 그 밖 선택지(이 세션 자동 승인 등) | 그 번호 숫자 |
  | 권한 거부 | `esc`(선택지 번호가 바뀌어도 같다). 화면의 선택지 글이 "No"로 시작하면 번호 대신 `esc`를 보낸다(P2) |
  | 승인하면서 지시 덧붙이기 | `tab`, `pane.send_text <글>`, `enter` |
  | 질문 하나, 단일 선택 | 그 번호 숫자(바로 제출) |
  | 자유 입력 | "Type something" 번호, `pane.send_text <글>`, `enter` |
  | 여러 개 고르기 | 고를 번호 숫자들, `down`을 (선택지 수 + 1)번, `enter`, 확인 화면에서 `enter` |
  | 질문 여러 개 | 질문마다 번호 숫자, 확인 화면에서 `enter` |
  | 계획 승인 | 그 번호 숫자 |
  | 질문 취소 | `esc` |

- 보내기 전 확인: `agent.send_keys`는 상태를 보지 않는다(idle에 `1`을 보내면 입력칸에 들어간다). 판은 보내기 직전에 `agent.get`으로 `blocked`인지, 카드의 요청(`PreToolUse`의 `tool_use_id`)에 아직 `PostToolUse`가 오지 않았는지 확인한다. 요청이 이미 풀렸으면(`stale`, `no_pending_ask`) 보내지 않고 카드를 닫는다. hook은 왔지만 herdr가 아직 `blocked`가 아니면(`not_blocked`) 보내지 않고 카드를 둔다. hook이 herdr보다 먼저 오는 짧은 틈이다(P2).
- 카드에서 답하지 않는 것: "Chat about this", "Tell Claude what to change"는 대화로 이어지므로 "터미널에서 답하기"로 보낸다. 판은 `ctrl+g`(Claude Code의 외부 편집기, 메모장이 뜬다)를 보내지 않는다. 노드 터미널에서 사용자가 누른 `ctrl+g`도 막고 안내 글을 보인다(P2).
- 거부 기록: 판에서 거부했으면 판이 보낸 키로 남긴다. 터미널에서 직접 거부한 경우는 hook이 없으므로 대화 기록에서 읽는다. 대화 기록에는 `is_error`인 `tool_result`("The user doesn't want to proceed with this tool use…"), 그 줄의 `toolUseResult: "User rejected tool use"`, 이어서 user 줄 `[Request interrupted by user for tool use]`가 남는다(P1).
- 단계: P1(데이터), P2(화면)

**A2. 턴이 끝났는데 아직 안 봤다(검토 대기)**
- 보여줄 것: 마지막 답 앞부분과 전체 보기, 턴에 걸린 시간, 끝난 시각, 바뀐 파일 수
- 백엔드: hook `Stop`의 `last_assistant_message`를 저장한다(E2: 이것으로 충분하다). 턴 시작(`UserPromptSubmit`)과 끝 시각을 기록한다. 세션 폴더가 git 저장소면 `git diff --stat`을 한 번 돌린다. 봤음 기록을 관리한다.
- 단계: P1, P2

**A3. 자리를 비웠다 돌아왔다(복귀 요약)**
- 보여줄 것: 마지막으로 본 뒤 바뀐 것만. 새로 생긴 내 차례, 새로 끝난 턴, 오류, 종료를 한 줄씩
- 백엔드: 모든 상태 변화를 시각순 이벤트로 SQLite에 남기고, "판을 마지막으로 본 시각 이후의 변화"를 `changes.since`로 조회할 수 있게 한다. 같은 세션의 같은 종류는 한 줄로 모으고 횟수를 붙인다.
- 판을 마지막으로 본 시각은 판 전체의 값이다. 창에 초점이 있고 보이는 동안 30초마다, 창을 떠날 때 남긴다(`board.markSeen`). 창을 다시 열거나 돌아왔을 때 5분 넘게 지났고 바뀐 것이 있으면 연다. 줄 종류는 내 차례, 오류, 끊긴 턴, 종료, 끝난 턴, herdr·백엔드 재시작이다(P3).
- 단계: P3(끝남)

**A4. 돌고 있는데 너무 조용하다(멈춤 의심)**
- 보여줄 것: "n분째 변화 없음", 마지막 화면 몇 줄
- 백엔드: 세션별 마지막 상태 이벤트와 hook 시각, `pane.read`로 읽은 마지막 줄들
- 단계: P1(데이터), P3(표시)

**A5. 턴이 실패했거나 claude가 끝났다**
- 보여줄 것: 실패 이유(예: rate limit) 또는 종료, 마지막 화면, 다시 시작하거나 이어 갈 수 있는지
- 백엔드: hook `StopFailure`의 오류 종류, `SessionEnd`와 herdr 해제 이벤트, `pane.read` 꼬리, 이어 가기에 필요한 세션 ID(`agent.get`의 `agent_session`)와 대화 기록 파일 존재 여부
- 단계: P1

### B. 말 걸기와 시작하기

**B1. 한 세션에 말을 건다(`@이름`)**
- 보여줄 것: 전달 상태. 대기 중(이유: 답 기다리는 중, 시작 중, 시작 대화상자, 사용자가 입력 중), 보냄, 제출 확인, 실패(이유). 대기 중이면 취소할 수 있다.
- 백엔드: 세션별 전달 대기열과 아래 규칙
  1. claude가 돌고 있는 패널(herdr `agent.list`에 있는 패널)에만 보낸다. 셸만 남은 패널에는 보내지 않는다.
  2. waiting이면 보내지 않는다. `agent.prompt`는 막힌 패널에 `agent_blocked` 오류로 거부한다(E0 3.2). 판은 대기열에 두었다가 waiting이 풀리면 다시 보낸다(최대 15분, symvibe와 같은 값).
  3. starting, trust_wait, working에서는 보내지 않는다. ready와 error에서만 보낸다. working 중에 `agent.prompt`를 부르면 Claude Code 자체의 다음 입력 대기열과 섞여 제출 확인이 언제 올지 모른다(P1).
  4. 사용자가 그 터미널에 최근 3초 안에 입력했으면 기다린다. 사람이 쓰던 글과 섞이지 않게 하기 위해서다.
  5. 줄바꿈을 LF로 맞춘 뒤 `agent.prompt`로 보낸다. 글과 Enter를 괄호 붙여넣기 모드에 맞춰 한 번에 넣고, 한글도 그대로 들어간다(E0 3.4). `pane.send_input`이나 `pane.send_text`를 쓸 때는 글에 CR을 넣지 않는다. 괄호 없이 들어간 CR은 줄마다 따로 제출된다(E3, E4).
  6. hook `UserPromptSubmit`이 오면 "제출 확인"으로 바꾼다. 보낸 뒤 30초 안에 오지 않으면 "확인 못 함"으로 끝낸다(P1). hook의 `prompt`는 보낸 글과 글자 그대로 같지 않을 수 있으므로 아래처럼 맞춘 뒤 비교한다(E3).
     - 4줄 이상이거나 800자를 넘는 글은 Claude Code가 `"\n\n<pasted_content id=\"xxxx\">\n" + 글 + "\n</pasted_content id=\"xxxx\">\n"`로 감싼다(`id`는 16진수 4자리, 세션마다 다름). 감싸기를 벗기고 비교한다.
     - 보낸 글은 CRLF → LF, 탭 → 공백 4칸으로 바꾼다.
     - 감싸지 않은 글은 끝의 공백과 줄바꿈이 잘리므로 양쪽 끝 공백을 잘라 비교한다.
- 여러 줄과 긴 글: `agent.prompt` 한 번으로 100KB(1,728줄)까지 한 턴으로 제출된다. 응답은 작은 글 약 0.32초, 100KB 0.89초다. 대기열은 응답을 기다리는 동안 다른 세션 전송을 막지 않는다(E3).
- 대화 보기(9.2 중간 얼굴)에 사용자 지시를 보여줄 때도 `<pasted_content>` 감싸기를 벗긴다.
- 여러 대상(`@c @d`)에 보낸 5줄 글도 두 세션에서 따로 확인됐다(P1).
- 단계: P1, P2

**B2. 여러 세션에 같은 말을 건다(`@그룹`, `@all`)**
- 보여줄 것: 대상 목록과 대상별 전달 상태
- 백엔드: 이름, 그룹, 전체를 대상 목록으로 풀고 각 세션의 대기열에 넣는다. 일을 나눠 서로 다른 지시를 쓰는 것(플래너)은 판이 만들지 않는다. 에이전트가 herdr 스킬로 한다(2026-10-30).
- 대상은 세션 이름을 먼저, 그다음 그룹 이름으로 푼다. 세션 이름과 그룹 이름은 겹칠 수 없다. `@그룹`으로 보낸 글은 그룹의 동시 실행 상한을 지키고, 넘으면 기다리는 이유 `batch_limit`로 기다린다. `@all`과 한 세션에 직접 보낸 글은 상한을 보지 않는다(P3).
- 단계: P1(이름 여러 개), P3(그룹, 끝남)

**B3. 새 세션을 시작한다**
- 보여줄 것: 이름, 폴더, 시작 상태, 첫 지시의 전달 상태. 처음 쓰는 폴더면 "신뢰 확인이 필요하다"를 미리 보여준다. 예상은 폴더와 상위 폴더의 신뢰 기록으로 한다(3절 trust_wait). 이 PC는 `C:/Workspace`가 신뢰돼 있어 그 아래 프로젝트는 묻지 않는다(E10).
- 백엔드:
  1. 세션 설정 파일을 만든다. 위치는 `<데이터 폴더>\sessions\<세션 ID>.json`이고, http hook(시간 제한 2초), 그 세션만의 hook 토큰, 세션 표시를 **값으로 직접** 쓴다. 작업 공간 `env`는 herdr를 다시 띄우면 되살아나지 않으므로 토큰을 거기 두지 않는다(E7). 수신기는 본문의 `session_id`로도 세션을 확인한다.
  2. `workspace.create { cwd, label }`로 작업 공간을 만든다.
  3. `agent.start { name, kind: "claude", pane_id, args }`로 claude를 띄운다. `args`: `--session-id <새 UUID>`, `--settings <1번 파일>`, `--no-chrome`(E1), 권한 모드, 모델
  4. 세션이 ready(또는 working, waiting, error)가 된 뒤 `pane.report_agent_session { pane_id, source: "herdr:claude", agent: "claude", seq, agent_session_id, resume_argv }`로 이어 가기 명령을 등록한다. `agent.start` 직후에는 herdr가 `resume_not_accepted`로 거부한다. 받아들인 등록은 `agent_session`도 채우므로, 신뢰 대화상자 중에 등록하면 trust_wait 신호 하나가 사라진다. 거부되면 1초마다 다시 시도한다(P1). ready까지 약 4초 동안 herdr가 다시 뜨면 등록을 잃는다. `resume_argv`는 `["claude", "--resume", <ID>, "--no-chrome", "--permission-mode", <모드>, "--settings", <1번 파일>]`이고 경로는 슬래시로 쓴다. 등록하지 않으면 herdr가 한 번만 다시 시작해도 `claude --resume <ID>`만 실행해 그 세션의 hook을 영영 잃는다(E7). 등록 뒤 판 전용 세션의 `session.json`에서 `agent_resume`을 읽어 저장을 확인한다(읽기만 한다).
  5. 첫 지시는 ready(herdr `idle`)가 된 뒤 B1 규칙으로 보낸다. `agent.start`는 신뢰 대화상자가 떠도 `agent_not_ready` 없이 바로 돌아온다(E10).
  6. herdr는 패널 셸에 `claude ...` 명령줄을 넣어 띄우므로 `claude`가 PATH에 있어야 한다. 이 PC는 `~/.local/bin/claude`다.
- 신뢰 대화상자에서 판은 대신 신뢰를 누르지 않는다. 카드는 "터미널에서 답하기"로 보낸다. 기본 선택이 "No, exit"라서 Enter만 보내면 claude가 끝난다(E1, E10).
- 설정 파일은 이어 가기 때 다시 읽히므로 세션이 판에 있는 동안 지우지 않는다. 판이 세션을 닫을 때(D2) 지운다.
- 단계: P1

**B4. 한꺼번에 여러 개를 돌린다(실험 묶음)**
- 보여줄 것: 묶음 진행(작업 중, 내 차례, 끝, 실패 개수)과 결과 목록
- 백엔드: 묶음(그룹)을 만들고, 동시 실행 상한을 넘는 세션은 대기열에 둔다. 묶음 단위로 상태를 집계하고 마지막 답을 모은다.
- 묶음 실행(`batch.run`)은 지시마다 세션 하나를 그룹 안에 띄운다. 상한을 넘는 항목은 세션을 띄우지 않고 대기열에 둔다. 진행은 대기열, 작업 중, 내 차례, 끝, 실패, 쉼으로 나눈다. 동시 실행 상한은 그룹마다 두고 기본값은 4다(1~32). 제출 확인 뒤 herdr `working`이 오기 전의 틈에도 그 세션을 "도는 중"으로 센다(최대 10초). 그러지 않으면 상한을 잠깐 넘는다(P3).
- 단계: P3(끝남)

**B5. 결과를 다음 세션에 넘긴다(포워드)**
- 보여줄 것: 누구의 결과를 누구에게 넘겼는지, 길이 때문에 잘린 부분
- 백엔드: 묶음이 모두 끝나면 마지막 답을 모아 길이를 제한하고, 받는 세션의 전달 대기열에 넣는다.
- 단계: 뺌(2026-10-30). 결과를 넘기는 것은 에이전트가 herdr 스킬로 한다(4절 F).

### C. 복구

**C1. 화면(Electron 창)을 껐다 켰다, 또는 화면이 죽었다**
- 보여줄 것: 같은 배치와 각 터미널의 현재 화면. 세션은 그동안 계속 돌았다.
- 백엔드: 세션은 herdr에서 계속 돈다. 창이 다시 붙으면 판 배치를 보내고, 가까이 보이는 노드에 제어기를 다시 붙인다. 제어기의 첫 프레임(약 5~12KB) 하나로 화면이 칸 단위까지 복원된다(E0 3.3, E4 2.3).
- 단계: P1, P2

**C2. 백엔드를 다시 시작했다**
- 보여줄 것: "백엔드가 n초 동안 꺼져 있었음". 그동안 세션 화면에 찍힌 hook 오류 글은 이 때문이라고 알린다.
- 백엔드: 같은 포트로 다시 연다. herdr `session.snapshot`과 `agent.list`로 현재 세션을 다시 읽고, 꺼져 있던 동안의 상태 변화는 herdr 현재 상태로 맞춘다. 그동안 놓친 hook(마지막 답 등)은 대화 기록에서 다시 읽는다.
- 단계: P1

**C3. herdr 서버를 다시 시작했거나 PC를 재부팅했다**
- 보여줄 것: 각 세션이 멈췄다가 이어졌는지, 이어 가지 못한 세션, "재시작으로 끊긴 턴"
- 백엔드(E7):
  - herdr 서버가 끝나면(정상 종료, 강제 종료 모두) 그 서버의 셸과 claude도 함께 끝난다. 고아 프로세스는 없고, claude는 `SessionEnd`(`reason: "other"`)를 보낸다.
  - 서버를 다시 띄우면 herdr가 작업 공간, 패널 ID, 에이전트 이름을 그대로 되살리고, 등록된 `resume_argv`(B3 4번)로 claude를 이어 간다. 대화 기록은 같은 파일에 이어진다. 판은 패널 ID와 세션 ID로 노드를 다시 찾는다(연결은 SQLite).
  - 상태는 다시 띄운 뒤 약 5초 동안 `unknown`이다(starting으로 본다). 다시 붙은 직후 `agent.list`는 이어 가기 전의 `idle`을 주므로 믿지 않는다. herdr가 꺼져서 끝난 세션은 새 상태 이벤트가 올 때까지 starting으로 둔다(P1).
  - 끝나지 않은 턴은 잃는다. 권한 요청을 기다리던 턴은 "User rejected"로 남고, 출력 중이던 턴은 답 없이 끝난다. 대화 기록에는 `[Tool call interrupted: the session ended before this call's result was recorded…]`가 남는다(P1). hook이나 herdr 상태로는 알 수 없으므로, 재시작 직전 working이나 waiting이던 세션은 "재시작으로 끊긴 턴"으로 표시하고 대화 기록 꼬리를 보여준다.
  - 한 턴도 돌지 않은 세션은 대화 기록 파일이 없어 `claude --resume`이 `No conversation found`로 끝난다. 이때 백엔드가 같은 패널에서 같은 `--session-id`와 설정 파일로 새로 띄우고 `resume_argv`를 다시 등록한다. 잃을 대화가 없으므로 묻지 않는다. 대화 기록이 있는데 이어 가기가 실패하면 손대지 않고 exited로 둔다(P1).
  - herdr는 `session.json`을 띄엄띄엄 저장한다. 띄운 지 얼마 안 된 세션은 서버가 죽으면 `resume_argv` 등록만이 아니라 작업 공간째로 잃는다(P3에서 확인). 그래서 판이 되살린다. herdr가 꺼져서 끝난 판 세션은 다시 붙은 뒤 아래처럼 한다.
    - 패널이 없으면 작업 공간을 다시 만든다. 대화 기록이 있으면 판의 인자(`--resume <ID> … --settings`)로 이어 가고, 없으면 같은 `--session-id`로 새로 띄운다.
    - 패널은 있는데 claude가 판의 설정 파일 없이 돌면(herdr 기본 이어 가기) `/exit` 뒤 판의 인자로 다시 이어 간다.
    - 15초 기다려도 claude가 뜨지 않으면 판이 이어 간다. 어느 경우든 `resume_argv`를 다시 등록한다.
  - 백엔드가 꺼진 동안 herdr가 다시 뜬 경우(재부팅 등)는 저장해 둔 herdr 서버 PID와 비교해 알아채고, 그때 working·waiting이던 턴을 끊긴 턴으로 남긴다. 이어 간 뒤 상태 이벤트가 다시 오지 않을 수 있어 `agent.get`으로 맞춘다(P3).
  - 창은 다시 뜬 세션에 터미널을 저절로 다시 붙인다. 다른 클라이언트가 패널을 가져간 경우는 빼앗지 않는다(P3).
  - 실제 PC 재부팅은 시험하지 않았다. 사용자 점검표가 `docs/P3.md` 8절 1번에 있다.
- 단계: P1(`resume_argv` 등록, 토큰 위치, 노드 다시 찾기, 빈 세션 새로 띄우기, 끊긴 턴 표시 값), P3(끊긴 턴의 대화 기록 꼬리 화면, 작업 공간 되살리기, 끝남)

### D. 자원과 안전

**D1. 세션이 너무 많다**
- 보여줄 것: 돌고 있는 세션 수, 세션별 메모리, 동시 실행 상한, 붙어 있는 제어기 수
- 백엔드: `pane.process_info`로 우리 패널의 프로세스를 찾아 메모리를 약 30초마다 잰다. 동시 실행 상한과 제어기 상한을 설정으로 둔다.
- `pane.process_info`에는 메모리가 없어서, 셸 PID를 얻은 뒤 Windows 프로세스 표(Win32_Process)에서 셸 아래 프로세스를 모두 더한다. 한 번 재는 데 약 1초다. 쉬는 claude 하나가 375~423MB, 패널 전체가 460~510MB였다(P3).
- 단계: P3(끝남)

**D2. 세션을 끈다**
- 보여줄 것: 끄기 전 확인, 끈 결과
- 백엔드: `/exit`를 보내 claude를 정상 종료하고, 필요하면 `pane.close` 또는 `workspace.close`로 패널을 닫는다. 판 전용 herdr 세션의 패널만 닫는다. `claude.exe`를 이름으로 끄지 않는다. 세션 설정 파일(B3 1번)도 이때 지운다.
- herdr 서버를 끄면 claude도 함께 끝나므로 claude를 따로 정리할 필요는 없다. 서버를 끄는 확인 창에는 "다시 띄우면 세션들이 이어 가기로 다시 뜨고, 진행 중이던 턴은 끊긴다"를 적는다(E7).
- 단계: P1

**D3. 판 전용 세션에 herdr 화면(TUI)을 붙인다**
- 보여줄 것: 경고. herdr 화면과 판의 제어기가 패널 크기를 두고 다툴 수 있다(E0 5절).
- 백엔드: 판 전용 세션에 다른 클라이언트가 붙었는지 알 수 있으면 알린다. herdr 소켓 API에는 클라이언트 목록이 없어서 두 가지로 본다(P3).
  1. 판 전용 세션의 서버 로그(`herdr-server.log`): herdr 화면은 `client connected … surface_active=…`와 `client disconnected`로 남고, 판의 제어기는 `direct terminal client connected` 등으로 남아 가를 수 있다. 로그 형식은 herdr 버전에 묶여 있다.
  2. `herdr.exe` 명령줄: 하위 명령 없이 `--session <판 세션>`으로 뜬 것과 `session attach <판 세션>`. 이 PC의 프로세스만 보인다.
- 단계: P3(끝남)

### E. 다른 곳의 세션과 함께 쓰기

E1과 E3은 2026-10-30에 빼기로 했다. 사용자는 장기적으로 CLI로 옮기므로 데스크톱 앱 세션과 판 밖의 herdr 세션은 보여주지 않는다. P3에서 만든 코드(`backend/src/desktop.mjs`, `backend/src/herdr/reader.mjs`, 창의 읽기 전용 카드, API, `mtask other`, `MTASK_REDACT`)는 P4에서 뺐다(`docs/P4.md` 1.1절). 아래 기록은 경위로 남긴다.

**E1. 데스크톱 앱 세션을 판에서 본다(읽기 전용, 뺌)**
- 보여줄 것: 제목, 폴더, 마지막 활동 시각, 마지막 답 앞부분, "앱에서 열기"
- 백엔드: 앱의 세션 JSON과 대화 기록 꼬리를 읽기만 한다. 정확한 상태(working, waiting)는 받을 수 없다. 받으려면 전역 hook이 필요한데, `~/.claude/settings.json`을 고치지 않는다는 규칙과 맞지 않는다. 그래서 마지막 활동 시각과 대화 기록으로 추정한 상태만 보여주고, 추정이라고 표시한다.
- 판 위의 읽기 전용 카드 하나로 보여준다. 보관하지 않은 세션 중 최근 3일 안에 활동한 것을 활동 순으로 24개 보인다. 추정 규칙(P3):
  - 앱 JSON의 `interruptedAwaitingPerson` → 기다림
  - 대화 기록 꼬리의 마지막 줄이 결과 없는 도구 사용이면 90초 안은 작업 중, 넘으면 "도구 결과 없이 멈춤(권한 대기일 수 있음)"
  - 마지막 줄이 답이면 쉬는 중, 사용자 쪽이면 5분 안은 작업 중, 넘으면 멈춤
- "앱에서 열기"는 `claude://claude.ai/epitaxy/local_<ID>` 모양의 딥 링크만 연다. 추정의 정확도는 사용자가 확인한다(`docs/P3.md` 8절).
- 단계: P3(끝남)

**E2. 오래 비운 세션으로 돌아간다(다시 들어가기 브리핑)와 떠날 때 메모**
- 보여줄 것: 마지막으로 내가 한 지시, AI의 마지막 답, 지금 상태, 기다리는 질문, 내가 남긴 메모
- 백엔드: 대화 기록에서 마지막 사용자 지시와 마지막 답을 뽑는다. 마지막 지시를 고를 때 `[Request interrupted …]`, `[Tool call interrupted …]`, `<local-command…>` 같은 Claude Code의 표시 줄은 건너뛴다. 메모를 저장한다(`note.add`). 요약이 필요하면 나중에 `claude -p`로 만든다.
- "오래"는 30분이다. "손댐"은 사람이 그 세션을 보거나(칩·`N`·알림으로 가거나 노드를 누름), 터미널에 입력하거나, 글을 보내거나, 카드로 답한 것이다. 떠날 때 메모 줄은 손댄 세션에서 다른 세션으로 옮길 때 20초 뜨고, 손대지 않으면 닫힌다(P3).
- 단계: P3(끝남)

**E3. 사용자가 기본 herdr 세션에서 돌리는 세션을 판에서 본다(읽기 전용, 뺌)**
- 보여줄 것: 작업 공간, 패널, 에이전트 상태, 화면 요약. 판 전용 세션의 노드와 구분해서 보여준다.
- 백엔드: 기본 세션의 소켓에 붙어 `agent.list`, `events.subscribe`, `pane.read`만 쓴다. 글 보내기, 제어기, 닫기는 하지 않는다. 이 세션들은 우리 hook이 없으므로 상세(무엇을 묻는지)는 없다.
- 읽기 모듈(`backend/src/herdr/reader.mjs`)은 이 세 호출 말고는 부르지 못하게 막는다. `session.snapshot`을 쓰지 않으므로 작업 공간 이름은 없고 ID만 보인다. 기본 세션이 꺼져 있으면 띄우지 않고 "꺼져 있음"으로 보인다. 대상은 `MTASK_OTHER_HERDR_SESSION`으로 바꿀 수 있다(시험용, 판 전용 세션은 거부)(P3).
- 단계: P3(끝남), P4에서 뺌(끝남)

### F. 세션끼리 연결(2026-10-30 추가, P4)

판이 하는 일은 세션을 띄우고, 세션끼리 연결해 주고, 그 연결을 보여주는 것이다. 일을 나누고 시키는 것은 에이전트가 herdr 스킬(`~/.agents/skills/herdr/SKILL.md`)로 직접 한다. herdr 패널 안의 에이전트는 `HERDR_ENV=1`과 자기 위치(`HERDR_WORKSPACE_ID`, `HERDR_PANE_ID`)를 받고, `herdr` 명령은 자기가 도는 herdr 세션에 붙는다. 판은 판 전용 herdr 세션 안에서 일어난 일만 본다.

Claude Code는 `~/.agents/skills`를 읽지 않는다. 그래서 판은 백엔드가 뜰 때 `<데이터 폴더>\plugin\multitask-herdr\`에 herdr 스킬 플러그인(스킬 글은 고정한 herdr의 `herdr --skill` 출력)을 만들고, 판이 띄우는 claude마다 `--plugin-dir`로 넘긴다. 짧은 안내(`--append-system-prompt-file`, 네 줄)로 herdr 스킬을 쓰라는 것, `--session`·`--machine`·`--remote`를 붙이지 않는다는 것, `[multitask 판]` 글은 판의 연결 알림이라는 것을 알린다. 이어 가기 명령(`resume_argv`)에도 같은 인자를 넣는다(P4).

**F1. 한 세션이 다른 세션에 일을 시킨다**
- 상황: 사용자가 세션 A에게 "w2:p1(또는 reviewer)에게 이걸 시켜"라고 한다. A는 herdr 스킬로 `herdr agent prompt <대상> "…" --wait`를 부르고, `herdr agent read`로 답을 읽는다.
- 보여줄 것: A에서 B로 가는 선. 선 위에 마지막 지시 앞부분과 상태(보냄, B 작업 중, B 끝남, B 내 차례). 선을 누르면 오간 기록.
- 백엔드: 판 전용 herdr 세션 안의 에이전트끼리 오간 지시를 알아채 "연결"과 "오간 일"로 저장한다. 후보 셋을 같은 사건으로 비교해 1을 기준으로 하고 3을 붙이기로 정했다. 2는 쓰지 않는다(P4, `docs/P4.md` 4절).
  1. Claude Code hook의 `PreToolUse`·`PostToolUse`(Bash, PowerShell)에서 `herdr agent prompt`, `herdr pane run`, `herdr agent start`, `herdr pane split` 명령 글 읽기. 누가, 누구에게, 무엇을 시켰는지 모두 준다. `PostToolUse`의 결과로 전달 끝과 `agent read`로 읽은 답도 얻는다. 판이 띄운 Claude Code 세션만 된다. 명령 치환(`$(…)`), 변수에 담은 대상, 스크립트 파일 안의 호출은 풀지 못한다.
  2. herdr 서버 로그: `agent.prompt`가 있었다는 것만 남는다(누가, 누구에게, 무엇을 모두 없음). 쓰지 않는다.
  3. herdr 이벤트(새 패널, 새 에이전트, 상태 변화): 받는 쪽 상태(작업 중, 끝남, 내 차례)와 새로 나타난 에이전트(F3)를 본다. 누가 시켰는지는 모른다.
- `--session`·`--machine`·`--remote`로 다른 곳을 부른 호출은 선을 긋지 않고 판 이벤트(`herdr_foreign_call`)로 남긴다. 대상이 아직 판에 없으면 120초 기다렸다가 그 에이전트가 판에 오르면 잇는다.
- 받는 쪽도 판이 띄운 Claude Code면 그쪽 hook(`UserPromptSubmit`, `Stop`)으로 제출과 답을 확인한다. 선의 색: 판에서 정한 역할은 파란 실선, 알아챈 지시는 보라 실선, 띄움은 초록 점선, 받는 쪽이 작업 중이면 움직이는 점선이다.
- 단계: P4(끝남)

**F2. 판에서 두 세션을 잇는다(역할 정하기)**
- 상황: 사용자가 판에서 A 노드에서 B 노드로 선을 끌고 역할(예: 리뷰어)을 적는다.
- 보여줄 것: 선과 역할 이름. 연결이 끊긴 경우(B가 끝남) 표시.
- 백엔드: 연결을 저장하고, A에게 B의 herdr 이름, 패널 ID, 역할을 알리는 글을 B1 규칙으로 보낸다. 그 뒤 A는 herdr 스킬로 B에게 일을 시킨다. 이어 가기나 패널 이동으로 패널 ID가 바뀌면 연결을 따라 고친다. 연결은 판을 다시 띄워도 남는다.
- 연결은 순서 있는 두 세션 쌍마다 하나이고 SQLite 표 `links`, `link_events`에 둔다. A에게 보내는 알림(P4에서 정함):
  ```
  [multitask 판] 연결 알림: herdr 에이전트 `rev`(패널 w6:p1, 종류 claude)가 너의 "리뷰어"이다.
  앞으로 "리뷰어에게 맡겨"처럼 이 역할을 부르면, herdr 스킬로 이 에이전트에게 일을 시키고 답을 받아 와라.
  일 시키기: herdr agent prompt rev "<할 일>" --wait
  답 읽기: herdr agent read rev --source recent-unwrapped --lines 80
  이 알림에는 "알겠다"고만 답해라.
  ```
- 끊기는 확인을 받는다. 역할이 있었으면 A에게 "연결 해제: … 더 이상 너의 "리뷰어"가 아니다"를 알린다. 오간 기록은 남는다. B의 패널 ID가 바뀌면 A에게 새 패널을 알린다(이 알림은 시험하지 않았다, `docs/P4.md` 7절 4번).
- 단계: P4(끝남)

**F3. 세션이 새 에이전트를 띄운다**
- 상황: A가 herdr 스킬로 패널을 나누고(`herdr pane split`) 새 에이전트를 띄운다(`herdr agent start reviewer --kind codex --pane …`).
- 보여줄 것: 새 노드가 A 옆 빈자리에 저절로 생기고, A에서 나온 선이 있다("A가 띄움").
- 백엔드: 지금은 판이 띄운 세션만 노드로 둔다(P1). 판 전용 herdr 세션에 새로 나타난 에이전트도 판에 올린다. 판의 `--settings` hook이 없으므로 상세는 herdr 상태와 화면으로만 얻는다. herdr에서 같은 탭의 패널은 크기를 나눠 쓰므로, 제어기가 노드 크기로 패널 크기를 바꿀 때 옆 패널과 다투지 않는지 본다.
- herdr `pane.agent_detected`(판이 모르는 패널)를 받아 올린다. 부모는 hook에서 본 띄운 명령(`agent start`의 이름이나 패널, `pane split` 결과 패널)으로 맞추고, 없으면 같은 작업 공간의 판 세션을 부모로 본다. 판에 올린 에이전트는 그룹에 넣지 않는다(P4).
- 끄기: A가 자기 작업 공간을 나눠 띄운 에이전트는 A와 같은 작업 공간에 있다. 같은 작업 공간에 다른 패널이 있으면 그 패널만 닫고, 없으면 D2처럼 작업 공간을 닫는다. 판이 띄운 세션에도 같다(P4).
- 같은 탭의 제어기: herdr 화면(TUI)이 붙지 않은 헤드리스 서버에서는 각 제어기가 자기 크기의 프레임만 받고 herdr 레이아웃은 바뀌지 않았다. 다투지 않는다(P4). 화면이 붙으면 D3 경고가 뜬다.
- 에이전트가 herdr로 직접 띄운 에이전트는 판의 설정(hook, 스킬 플러그인, 권한 모드)을 받지 않고 그 하네스의 사용자 설정을 따른다. 판의 명령(`mtask child`)으로 띄운 하위 세션은 받는다(4절 K).
- 단계: P4(끝남)

**F4. 워크트리로 따로 개발한다**
- 상황: 사용자가 세션에게 "이 기능은 워크트리를 따로 파서 개발해"라고 한다. 하네스가 자기 규칙대로 워크트리를 만들고 그 안에서 일한다. 또는 에이전트가 `herdr worktree create`로 연결된 작업 공간을 만든다.
- 보여줄 것: 노드에 워크트리 경로와 브랜치. 같은 저장소의 세션끼리의 관계(본 저장소, 워크트리).
- 백엔드: 판은 워크트리를 만들지 않고 규칙도 정하지 않는다. hook의 `cwd`(Claude Code는 셸에서 `cd`한 폴더를 알린다)와 git 조사(`rev-parse --git-dir --git-common-dir`)로 알아낸다. hook이 없는 세션은 herdr `pane.get`의 `foreground_cwd`를 15초마다 본다. herdr 작업 공간 묶음(worktree group)은 쓰지 않았다(P4).
- 같은 저장소 선은 워크트리 세션이 있을 때만, 워크트리 세션마다 하나(이어진 세션, 없으면 가장 늦게 만든 본 저장소 쪽 세션)로 긋는다. 모든 세션을 이으면 판이 선으로 덮인다.
- Claude Code의 워크트리 기능(`claude --worktree`, `EnterWorktree`)으로 들어간 세션은 시험하지 않았다(`docs/P4.md` 7절 5번).
- 단계: P4(끝남)

**F5. Claude Code가 아닌 에이전트를 띄운다**
- 보여줄 것: 노드에 에이전트 종류(claude, codex, hermes 등)와 상태
- 백엔드: `agent.start { kind }`로 띄운다. herdr가 아는 종류는 `herdr agent`가 보여준다. 상태는 herdr 상태(idle, working, blocked, done, unknown)만 쓰고, 묻는 내용과 마지막 답은 화면(`pane.read`)에서 읽는다. 승인 카드의 키 순서는 Claude Code만 안다(E9). 다른 종류는 "터미널에서 답하기"로 보낸다.
- 다른 종류는 hook, 이어 가기 등록, 신뢰 예상 없이 실행 인자를 그대로 넘긴다. 보낸 뒤 herdr `working`이면 제출 확인으로 친다(`agent.prompt` 응답보다 먼저 와도 된다). 마지막 답은 턴이 끝날 때 `pane.read recent_unwrapped`에서 고른다(`answerSource: screen`). 끄기는 `/exit` 대신 `ctrl+c` 두 번이다. 판의 답하기 API는 `answer_in_terminal` 오류로 거부한다(P4).
- 종류 목록은 `herdr agent` 도움말의 `kinds:` 줄과 `where.exe`로 깔린 것을 찾는다. 깔린 것을 위에 두고 없는 것은 고를 수 없다.
- codex는 시작하자마자 저장소 루트 신뢰를 묻는다. 판은 수락하지 않는다. codex 턴(제출 확인, 마지막 답, 실행 승인 카드)은 따로 검증하지 않는다. 다른 종류는 웬만하면 각자 알아서 돈다(2026-10-30 사용자 결정).
- 단계: P4(끝남)

### G. 리포지토리 워크스페이스(2026-10-30 추가, P5)

사용자의 세션은 모두 어떤 리포지토리에 묶여 있다. 판은 리포지토리 하나를 워크스페이스 하나로 보고, 워크스페이스마다 판 하나를 둔다. 워크스페이스는 판 전용 herdr 세션 안의 세션(판이 띄운 것, 에이전트가 띄운 것, 일반 셸)만 담는다. 판 밖에서 연 세션은 다루지 않는다(BRIEF 3절 "범위 밖"). 판이 띄우는 세션은 지금처럼 herdr 작업 공간을 하나씩 쓴다. herdr 작업 공간을 리포지토리 단위로 바꾸지 않는다.

같은 날 단일 캔버스로 다시 정했다(4절 H, P6). 아래에서 워크스페이스마다 판을 나누는 부분(G1의 위쪽 워크스페이스 줄과 판 바꾸기, G3의 들어갈 때 맞추기와 세션 줄, G4의 워크스페이스 바꾸기와 `@all` 범위)은 H가 대신한다. 워크스페이스 키, `cd` 표시, 빈 워크스페이스, 이전 판 옮기기(G1), 일반 셸(G2), 워크스페이스를 가로지르는 내 차례(G4)는 그대로다.

**G1. 리포지토리를 워크스페이스로 묶는다**
- 보여줄 것: 위쪽 워크스페이스 줄("내 차례" 줄 아래 따로 한 줄). 워크스페이스마다 이름(저장소 폴더 이름, 겹치면 `부모/이름`, 그래도 겹치면 전체 경로), 저장소(`⎇`)인지 폴더(`▢`)인지, 세션 수, 작업 중 수, 내 차례 수, 검토 대기 수. 지금 고른 워크스페이스를 표시한다. 셸은 작업 중과 검토 대기에 세지 않는다(P5).
- 백엔드: 세션의 워크스페이스 키는 시작 폴더의 git 공통 폴더(`git rev-parse --path-format=absolute --git-common-dir`, 역슬래시·끝 슬래시·대소문자를 맞춤)다. 순수 함수는 `backend/src/workspaces.mjs`, git 조사는 `git.mjs`의 `workspaceOf`다(P5). 워크트리도 본 저장소와 같은 키다. git 저장소가 아니면 그 폴더 자체가 키다. 판에 올린 에이전트와 셸은 패널 폴더(herdr `cwd`)로 정한다.
- 세션이 다른 저장소로 `cd`해도 워크스페이스를 옮기지 않는다(BRIEF 4절 "자리는 사람이 정하고 시스템은 지킨다"). 노드에 "다른 저장소에서 일하는 중(…)"을 표시한다. 같은 저장소의 워크트리로 들어간 것은 4절 F4처럼 브랜치와 워크트리만 보인다.
- 워크스페이스 줄의 순서는 처음 생긴 순서로 고정한다.
- 세션이 하나라도 생기면 워크스페이스가 저절로 생긴다. 사용자가 "+ 리포 열기"로 폴더를 골라 빈 워크스페이스를 만들 수도 있다. 세션이 모두 닫혀도 워크스페이스는 남고, 비어 있을 때만 닫을 수 있다(`not_empty`). 닫으면 그 판의 그룹 영역도 지운다(P5).
- 그룹은 한 워크스페이스 안에 있다. 그룹 폴더와 다른 워크스페이스의 폴더로 그룹 안에서 띄우거나 그룹 폴더를 다른 워크스페이스로 바꾸면 거부한다(P5).
- 새 세션 대화상자의 폴더는 지금 워크스페이스의 저장소 루트가 기본이다. 다른 저장소의 폴더를 고르면 그 세션은 그 저장소의 워크스페이스에 생긴다.
- P4까지 쓰던 판(`board.db`)을 옮길 때 세션은 시작 폴더로 워크스페이스를 정하고 노드 자리는 그대로 둔다. 그룹은 소속 세션의 워크스페이스(섞여 있으면 가장 많은 쪽, 비었으면 그룹 폴더, 둘 다 없으면 첫 워크스페이스)로 정한다. 옛 판 하나의 뷰포트는 마지막에 본 워크스페이스(없으면 세션이 가장 많은 워크스페이스)로 옮긴다. 백엔드가 뜰 때마다 `backend/src/migrate.mjs`를 부르고, 옮길 것이 없으면 아무것도 하지 않는다(P5).
- 단계: P5(끝남)

**G2. 워크스페이스 안의 세션을 빠짐없이 보여준다**
- 보여줄 것: 판 전용 herdr 세션에서 그 워크스페이스에 속한 모든 패널. 에이전트 세션(Claude Code, 다른 종류, 판에 올린 것)과 일반 셸.
- 백엔드: herdr `pane.created`, `pane.closed`, `pane.exited`, `pane.agent_detected`와, 다시 맞출 때의 `pane.list`로 판 전용 herdr 세션의 모든 패널을 추적한다. 패널 하나가 노드 하나다. 판이 모르는 패널에 에이전트가 없으면 종류 `shell`로 올리고, 나중에 그 패널에 에이전트가 나타나면 새 노드를 만들지 않고 같은 노드의 종류만 바꾼다(4절 F3의 판에 올리기와 합친다). 판이 띄운 에이전트가 끝나 패널만 남은 경우는 지금처럼 exited로 둔다(이어 가기 규칙 그대로). 판이 띄우지 않은 에이전트(판에 올린 것, 셸에서 띄운 것)가 끝나면 같은 노드를 셸로 되돌린다(P5).
- herdr 이벤트: 셸에서 `exit`하면 `pane_exited`만 오고 `pane_closed`는 오지 않는다. 작업 공간을 닫아도 패널마다 `pane_closed`가 오지 않는다. 둘 다 처리한다(P5).
- 셸의 상태: `shell_idle`(프롬프트에서 쉼)과 `shell_running`(명령 실행 중). Windows에서 herdr `pane.process_info`는 셸(`powershell.exe`)만 주고 셸 아래 명령은 주지 않는다. 그래서 2초마다 화면 끝 줄이 프롬프트(PowerShell `PS …>`, cmd `C:\…>`, `$`·`#`)인지로 쉬는지 보고, 명령 글은 마지막 프롬프트 줄에서, 프로세스 이름(예: `PING.EXE`)은 셸 PID의 자식(Win32_Process, 새 명령이 시작될 때와 도는 동안 30초마다)에서 얻는다. 화면 추정이라 출력이 화면을 넘기면 마지막 명령을 잃을 수 있다. 셸에는 hook과 승인 카드가 없다(P5).
- 셸에는 명령 바로 글을 보내지 않는다(BRIEF 5절 전달 규칙). `@셸이름`은 `not_agent` 이유로 거부한다. 터미널 입력, 화면, 끄기(확인 뒤 패널 닫기)는 된다.
- 새 세션 대화상자에 종류 "셸(PowerShell)"을 더한다. `workspace.create`만 하고 `agent.start`는 하지 않는다.
- 에이전트가 `pane split`만 하고 둔 빈 패널도 셸 노드로 보인다. 에이전트가 나눈 패널에 `agent start`로 에이전트를 띄우면 먼저 셸 노드로 올라왔다가 같은 노드의 이름과 종류가 바뀐다(P5).
- 단계: P5(끝남)

**G3. 늘 보이는 오버뷰**
- 보여줄 것: 워크스페이스에 들어가면 그 워크스페이스의 세션이 모두 화면에 들어오도록 맞춘다. 작게 보이는 노드는 9.2의 중간·멀리 얼굴이 된다. 판 아래쪽(명령 바 위)에 세션 줄을 늘 띄운다. 세션마다 이름, 종류, 상태 필, 브랜치가 있고, 누르면 그 노드로 간다. 지금 화면 밖에 있는 세션은 세션 줄에서 표시한다.
- 세션 줄은 접거나 숨기지 않는다. 불러야 보이는 목록이 아니다. 화면 밖 세션은 `↗`와 점선 테두리, 2분 안에 생겨 아직 가 보지 않은 세션은 "새", 다른 저장소에서 일하는 세션은 `↪ 저장소`로 표시한다. 워크스페이스 줄의 지금 칸을 다시 누르면 모두 보이게 다시 맞춘다(P5).
- 새 세션이 생기면 그 워크스페이스 판의 빈자리에 놓는다. 사람이 보고 있는 화면을 저절로 옮기지 않는다. 화면 밖에 생겼으면 세션 줄에서 표시한다.
- 노드 자리와 크기는 지금처럼 세션마다 저장한다. 빈자리 계산은 같은 워크스페이스의 노드와 그룹만 본다. 앱을 다시 열면 마지막에 본 워크스페이스로 들어가고 모든 세션이 보이도록 맞춘다. 뷰포트는 워크스페이스마다 저장하지만, 들어갈 때는 늘 모두 보이게 맞추므로 저장한 뷰포트로 되돌리지 않는다(P5).
- 단계: P5(끝남)

**G4. 워크스페이스를 가로지르는 것**
- 내 차례, 검토 대기, 문제 칩은 모든 워크스페이스를 가로지른다(BRIEF 4절). 칩에 워크스페이스 이름을 붙이고, 누르면 그 워크스페이스로 바꾸고 노드로 간다. OS 알림과 `N`도 같다.
- 연결(4절 F)이 다른 워크스페이스의 세션으로 이어지면 선 대신 노드 가장자리에 "→ @이름(워크스페이스)" 표시를 둔다. 누르면 그 워크스페이스로 간다.
- `@all`은 지금 보고 있는 워크스페이스의 에이전트 세션으로 바꾼다. 보이지 않는 저장소의 세션에 글이 가지 않게 하기 위해서다. `@이름`과 `@그룹`은 워크스페이스와 상관없이 이름으로 찾는다(이름은 판 전체에서 하나). `@그룹`은 그룹 안의 셸을 뺀다. 여러 대상 중 셸이 하나라도 있으면 전체를 보내지 않는다(P5).
- 자원 표시(D1)와 D3 경고는 판 전체 기준 그대로다.
- 단계: P5(끝남)

### H. 단일 캔버스와 관계 표현(2026-10-30 추가, P6)

사용자가 연 모든 CLI 세션을 워크스페이스와 상관없이 캔버스 하나에 둔다. 그 위에서 세션 사이의 관계를 선과 붙여 묶기로 보여주고, 전체를 한눈에 보며 질문과 요청을 찾고, 어느 세션이든 바로 들어간다. P5의 워크스페이스별 판을 대신한다(4절 G 머리말).

**H1. 한 캔버스와 워크스페이스 영역**
- 보여줄 것: 모든 세션 노드가 한 캔버스에 있다. 워크스페이스마다 그 세션들 뒤에 영역(배경과 이름표: 저장소 이름, `⎇`/`▢`, 세는 값)을 깐다. 영역은 안의 노드, 덩어리, 그룹을 감싸도록 저절로 커지고 줄어든다. 영역 이름표를 끌면 안의 것이 모두 함께 움직인다.
- 새 세션은 그 워크스페이스 영역 안이나 바로 옆 빈자리에 놓는다. 영역끼리 겹치지 않게 한다. 새 워크스페이스는 다른 영역과 겹치지 않는 빈자리에 생긴다.
- P5 판을 옮길 때: P5는 워크스페이스마다 판이 따로라 노드 자리가 서로 겹친다. 워크스페이스마다 노드 묶음을 통째로 옮겨 겹치지 않게 늘어놓고, 워크스페이스 안의 상대 자리는 지킨다.
- 백엔드: 영역 계산과 빈자리는 순수 함수(창과 같이 씀). 워크스페이스마다 영역의 자리를 저장한다.

**H2. 바로 가기: 워크스페이스 단추와 검색**
- 아래쪽(명령 바 근처)에 워크스페이스 단추를 늘 둔다. 누르면 그 영역이 화면에 들어오게 간다. 단추에 세는 값(세션, 작업 중, 내 차례, 검토 대기).
- 검색(`Ctrl+F`): 세션 이름, 워크스페이스 이름, 기다리는 질문, 사용자 요청(최근 지시), 마지막 답, 메모에서 찾는다. 결과를 키보드로 오가고, 고르면 그 노드로 간다.
- 백엔드: `search.query { q, limit }`. 판 기록(세션 요약, 이벤트의 지시·답·질문, 메모, 출력)에서 찾는다. 대화 기록 파일 전체를 뒤지는 검색은 하지 않는다(8절).
- P5의 위쪽 워크스페이스 줄과 세션 줄은 이 둘로 바꾼다. 내 차례 칩과 `N`은 그대로다.

**H3. 전체 조망: 질문과 요청이 읽히는 오버뷰**
- 멀리 얼굴(9.2)을 다시 그린다. 이름, 상태, 기다리는 질문(가장 크게), 마지막 사용자 요청 한 줄, 마지막 답 한 줄. 캔버스 배율이 작아도 이 글이 읽히도록 글자 크기를 화면 기준으로 둔다.
- 기다리는 노드는 눈에 띄게, 오래 쉬는 노드는 흐리게 한다.

**H4. 바로 들어가기**
- 노드를 누르면(어느 얼굴에서든) 그 노드로 가서 가까이 얼굴로 맞추고 터미널에 초점을 준다. 터미널이 붙기 전에 친 글을 잃지 않는다.

**H5. 붙여 묶기(도킹)**
- 두 노드 이상을 가장자리끼리 붙여 한 덩어리로 둔다. 터미널 화면 분할처럼 사이에 틈이 없고, 분할선을 끌면 이웃한 노드의 크기가 함께 바뀐다. 덩어리는 함께 움직인다. 초기 구현은 가로 한 줄이나 세로 한 줄이면 된다.
- 붙이기: 노드를 끌어 다른 노드 가장자리에 가까이 가면 붙을 자리를 보이고, 놓으면 붙는다. 떼기: 덩어리에서 노드를 끌어내거나 메뉴의 "떼기".
- 처음부터 붙이는 경우: herdr에서 같은 탭에 나뉜 패널(에이전트가 `pane split`으로 나눈 패널, 4절 F3·G2). herdr의 나눈 방향(오른쪽·아래)대로 붙인다. 나머지 관계(역할, 시킴)는 선으로 둔다. 언제 선 대신 붙일지는 써 보고 정한다(8절).
- 붙은 노드 사이의 연결은 선 대신 분할선 위의 작은 표시(역할, 받는 쪽 상태)로 보인다.
- 붙여 묶기는 판의 배치일 뿐이다. herdr 레이아웃과 패널 크기는 바꾸지 않는다. 제어기는 지금처럼 노드 크기로 화면을 받는다.
- 백엔드: 덩어리(구성 노드, 방향, 비율)를 저장하는 표와 API(`dock.create`, `dock.update`, `dock.remove`). 노드가 닫히면 덩어리에서 빠지고, 하나만 남으면 덩어리가 풀린다. 덩어리는 한 워크스페이스 안에 있다.

**H6. 골라서 묶는 그룹**
- 캔버스에서 노드 몇 개를 고르고(`Ctrl`+누르기, 상자 고르기) "묶기"를 누르면 그룹이 생기고 그 노드들 뒤에 배경(이름, 색)이 깔린다. P3 그룹(halo)과 같은 것이다(동시 실행 상한, 묶음 실행 그대로). 그룹은 한 워크스페이스 안에 있다. 다른 워크스페이스의 노드를 섞어 고르면 거부한다.
- 그룹 배경은 안의 노드를 감싸도록 저절로 맞춘다. "풀기"는 그룹만 지우고 노드는 그대로 둔다.
- 백엔드: `group.create { members }`(고른 세션으로 만들고 배경을 맞춤), `group.ungroup`.

**H7. 관계가 드러나는 크기와 정리**
- 노드 크기 단계: 크게, 보통, 작게. 사람이 바꾼다.
- "정리"(워크스페이스 영역 메뉴, 사람이 누를 때만): 연결(역할, 시킴, 띄움)을 따라 시키는 쪽을 왼쪽에 크게, 받는 쪽을 오른쪽에 작게 놓는 나무 배치. 덩어리와 그룹은 한 덩어리로 다룬다. 바로 앞 자리로 한 번 되돌릴 수 있다.
- 자리는 사람이 정하고 시스템은 지킨다(BRIEF 4절). 저절로 옮기는 것은 새 노드를 놓을 때뿐이고, 정리는 사람이 누를 때만 한다.
- 백엔드: 정리 배치는 순수 함수(창과 같이 씀), `board.arrange { workspace, apply? }`.

**H8. 명령 바**
- `@all`은 캔버스 전체의 에이전트 세션으로 되돌린다. P5의 "지금 워크스페이스" 범위는 단일 캔버스에서 뜻이 없다. 셸은 계속 뺀다. `session.send`에 `workspace`를 주면 그 워크스페이스만 받는다(mtask `--ws`, 창에는 없음).

**만들며 정한 것(P6a, P6c).** 세부와 API는 `docs/P6a.md` 1절, `docs/P6c.md` 1절이다.
- H1: 영역은 안의 노드·그룹·메모·칸반을 감싸고(이름표 자리 72), 영역 사이 틈은 240이다. 사람이 노드나 영역을 끌어 다른 영역과 새로 겹치게 놓으면 되돌린다. 크기를 키워 겹치는 것은 막지 않는다. P5 판은 워크스페이스마다 통째로 옮겨 늘어놓는다(`migrate-canvas.mjs`, 뜰 때마다 부르고 이미 옮겼으면 아무것도 하지 않음). 뷰포트는 캔버스 하나에 하나다.
- H2: 검색은 이름, 워크스페이스, 질문, 마지막 요청·답, 지난 요청·답(hook, 판이 보낸 글), 받은 지시, 메모, 칸반(제목, 열, 카드), 출력(hook 없는 세션의 화면 답)에서 찾는다. 세션마다 가장 잘 맞은 것 하나. `Ctrl+F`는 터미널 안에서도 연다.
- H3: 노드가 화면에서 160px보다 낮으면 기다리는 노드 위에 말풍선(질문, 요청)을 띄운다. 기다리는 노드는 화면 기준 두께의 테두리가 깜빡이고, 30분 넘게 쉬는 노드는 흐리다.
- H4: 터미널이 붙기 전에 친 키는 창이 모았다가 붙자마자 넣는다(8초, 한글 조합 중인 키는 빼고).
- H5: 덩어리 표는 구성 노드 순서와 방향만 둔다. 크기는 노드 표에 있다. 끌어 붙이기는 `dock.attach`, 양 끝에만 붙는다(한 줄). 구성 노드 머리줄을 끌면 덩어리째 움직이고 `Alt`+끌기나 메뉴로 뗀다. 가운데 노드가 닫히면 남은 노드가 틈 없이 당겨진다.
- H6: 묶기로 다른 그룹의 노드를 고르면 새 그룹으로 옮기고, 그래서 비게 된 그룹은 지운다.
- H7: 크기 단계는 1040×660, 720×460, 480×300(`board.setSize`). 정리는 그 워크스페이스의 메모·칸반도 크기 그대로 놓는다. 정리 결과가 다른 영역과 겹치면 영역째로 빈자리로 옮긴다. 되돌리기는 크기 단계와 메모·칸반 자리까지 한 번.
- 자리가 바뀌면 판 이벤트 `node_moved { from, to, cause }`를 남긴다(P5의 설명하지 못한 노드 이동을 다시 볼 때 쓴다). 창 시험에서 끄는 점이 캔버스 가장자리에 닿으면 React Flow가 화면을 저절로 밀어 노드를 더 멀리 옮긴다(P6c에서 봄). 그 이동의 한 후보다.
- 단계: P6(끝남)

### I. 남은 기능(2026-10-30 추가, P6)

BRIEF 5절의 "그 뒤 후보" 중 음성과 스튜디오를 뺀 나머지다. 백엔드는 다 만들고 화면은 초기 구현까지 한다. symvibe의 동작은 `docs/research/symvibe.md`를 참고만 한다.

**I1. 출력 보기**
- 끝난 답이 길면(약 80자 또는 세 문단을 넘으면) 노드 머리줄에 "출력 보기"가 나온다. 대화 기록에서 마지막 답을 읽어 문서(마크다운)로 보여준다. hook이 없는 세션은 화면에서 고른 답이다.
- 거기서 바로 답장을 보낸다(B1 규칙). `.md`로 저장한다. 저장 위치는 판 데이터 폴더의 `outputs/<워크스페이스 이름>/`이다. 사용자 저장소 안에는 쓰지 않는다.
- 백엔드: `output.get { session, turn? }`(지난 턴들도), `output.save { session, turn? }`.

**I2. 명령 바 대화 기록(Thread)**
- 명령 바에서 보낸 글과 결과(대상, 전달 상태, 완료 보고)를 시간순으로 남긴다. 완료 보고는 받는 쪽의 마지막 답을 최대 4,000자까지 쓴다. 기다리다 버려진 전달(15분)도 남긴다. 최근 500개를 둔다.
- 백엔드: `thread.list { before?, limit }`, 이벤트 `thread.item`. 전달 기록(B1)과 마지막 답에서 만든다.

**I3. 메모 노드**
- 캔버스에 글 노드를 둔다. 마크다운, 자리와 크기를 저장한다. 워크스페이스 영역 안에 두면 그 워크스페이스 소속이다. 검색 대상이다.
- 백엔드: `memo.create`, `memo.update`, `memo.delete`, `memo.list`.

**I4. 칸반(체크리스트) 노드**
- 열(기본: 할 일, 하는 중, 끝)과 카드를 가진 노드. 카드를 세션에 이을 수 있고, 이은 카드에는 세션 상태가 보이며 누르면 그 세션으로 간다. 열 하나짜리는 체크리스트다.
- 백엔드: `kanban.create`, `kanban.update`(열·카드 추가, 옮기기, 이름 바꾸기, 세션 잇기), `kanban.delete`, `kanban.list`.

**I5. 루프**
- 같은 지시를 조건에 따라 다시 보낸다. 시작 조건: 일정 주기(1분~24시간), 에이전트가 쉴 때(ready가 될 때), 마지막 답이나 화면에 특정 글이 나올 때. 멈춤 조건: 횟수, 시간, 마지막 답에 특정 글(목표 달성 표시), 사람이 멈춤.
- 내 차례(waiting, trust_wait)인 세션은 그 차례를 건너뛴다. 전달은 B1 규칙과 그룹 동시 실행 상한을 따른다. 셸에는 걸 수 없다.
- 백엔드가 꺼지면 루프도 멈추고, 다시 뜨면 남은 횟수와 시간으로 이어 간다. 토큰을 쓰므로 만들 때 확인을 받는다(`confirm`).
- 백엔드: `loop.create { session | group, prompt, trigger, stop, confirm }`, `loop.pause`, `loop.resume`, `loop.delete`, `loop.list`, 이벤트 `loop.updated`. 루프가 보낸 지시는 Thread에 남는다.

**I6. 미션 맵**
- 덮개 화면. 세 열: 명령 바(사람)와 지시를 내리는 세션 → 그룹 → 세션. 누가 누구에게 지시하는지 선으로 잇는다(연결, 전달 기록, 루프).
- 백엔드: `mission.graph`. 판 데이터에서 노드(사람, 세션, 그룹)와 선(역할, 시킴, 띄움, 명령 바 전달, 루프)을 만들어 준다.

**I7. 트레이 상주**
- 설정으로 켠다(기본 꺼짐). 켜면 창을 닫아도 앱이 트레이에 남아 OS 알림을 계속 띄운다. 트레이 메뉴: 열기, 내 차례 수, 끝내기. 알림을 누르면 창을 다시 열고 그 노드로 간다.
- Electron main에서 한다. 설정은 `settings.get`, `settings.set`(판 기록)에 둔다.

**I8. 복구 확인**
- herdr를 다시 띄운 뒤 셸 노드와 판에 올린 패널이 어떻게 되는지 확인하고 맞춘다(`docs/P5.md` 5절 4번).

**만들며 정한 것(P6b, P6c).** API 문서는 `docs/P6b.md` 3절, 화면은 `docs/P6c.md` 1·2절이다.
- I1: 긴 답은 앞뒤 공백을 뺀 80자 초과 또는 문단 3개 초과(요약 `output.long`). 턴은 사람이 쓴 지시 하나로 시작하고 답은 그 턴의 마지막 assistant 줄이다. hook이 없는 claude는 herdr가 아는 대화 ID로 대화 기록을 찾고, 없으면 화면 답이다. 저장 파일은 `<세션>-t<턴>-<시각>.md`. 출력 보기는 캔버스 오른쪽에 떠 있는 창이고, 마지막 턴을 보는 동안 새 답이 오면 다시 읽는다. 답장은 `session.send { source: 'output' }`.
- I2: Thread에는 모든 `session.send`와 루프 지시가 남고, 연결 알림·새 세션 첫 지시·묶음 실행 지시는 남지 않는다. 보고는 제출 확인 뒤 턴이 끝나 ready·error가 될 때 붙는다. 창에서는 명령 바 위에 펼치는 판이다.
- I3·I4: 메모·칸반은 놓은 노드의 가운데가 영역 안이거나 영역에 걸치거나 영역 바로 옆(120 안)이면 그 워크스페이스 소속이다. 새 메모·칸반은 보던 화면 가운데(`near`)의 빈자리에 생긴다. 빈 워크스페이스를 닫으면 메모·칸반은 지우지 않고 소속만 푼다. 글이 있는 메모, 카드가 있는 칸반·열은 지울 때 묻는다. 열 하나짜리 칸반(체크리스트)은 카드 앞 상자로 끝을 표시한다(글에 줄 긋기). 마크다운은 의존성 없이 직접 그린다(HTML은 그리지 않음).
- I5: "횟수"는 보낸 차례 수다(주기 루프의 그룹은 한 차례에 멤버 모두). 주기와 쉴 때 조건은 만들자마자 한 번 보내고(주기는 `immediate`로 끌 수 있음), 글 조건은 만든 뒤 새로 나온 것만 본다. 건너뛰기 까닭은 `needs_you`, `busy`, `not_ready`. 돈 시간은 백엔드가 도는 동안만 세고, 다시 뜨면 다음 차례를 꺼진 시간만큼 민다. 만든 루프의 조건을 고치는 API와 화면은 없다(지우고 다시 만든다). 창은 두 단계 확인 대화상자와 노드·그룹 배지·목록이다.
- I6: 미션 맵은 위쪽 줄 아래를 덮는 화면이고 `M`으로 연다. 분류 거르기 칩이 있고, 가운데 열 상자를 지나는 선은 아래 길로 돌린다. 실시간 이벤트는 따로 없고 관련 이벤트가 오면 다시 부른다.
- I7: 트레이를 켜면 Electron main이 백엔드에 따로 붙어 설정을 따른다(`app/src/main/tray.mjs`). 트레이 상주 중 main은 백엔드를 띄우지 않고 2초마다 다시 붙는다. 창이 없는 동안의 알림 규칙은 창과 같다. 창에서는 위쪽 ⚙ 설정이다.
- I8: herdr를 다시 띄우면 셸 노드와 판에 올린 패널은 패널이 남으면 같은 노드로 남고(에이전트가 없으면 셸), 패널이 없어지면 판에서 뺀다. 판이 띄운 셸이 패널째 없어지면 되살리지 않는다. 셸에서 돌던 명령은 "끊긴 명령"으로 남긴다(`interruptedTurn`, 창의 띠와 배지). 셸 화면은 좁은 패널에서도 프롬프트를 알아보도록 줄바꿈을 푼 최근 줄(`recent_unwrapped`)로 읽는다.
- 단계: P6(끝남)

### J. 세션 되찾기와 사이드바(2026-10-31 추가, P7)

사용자 피드백: 앱을 꺼도 다음에 켜면 기존 세션을 다시 찾아와야 하고, 평소에는 닫힌 사이드바가 열린 리포의 목록을 보여야 한다. "기존 세션"은 판에 있던 세션과, 열린 워크스페이스의 판 밖 Claude Code 대화 전부다(사용자 답). 사이드바에는 리포와 그 안의 세션을 보인다(사용자 답).

**J1. 다시 켜도 판이 그대로**
- 상황: 창만 닫음, 트레이에서 끝내기, 백엔드와 herdr까지 끔(`mtask herdr stop`, `backend stop`), PC 재부팅. 다음에 앱을 켜면 판에 있던 세션이 같은 자리, 같은 덩어리·그룹·연결로 돌아온다.
- 지금 되는 것: 창을 닫아도 백엔드와 herdr는 돈다(P2). 백엔드는 뜰 때 herdr가 없으면 띄우고(`ensureHerdr`), 판이 띄운 claude는 `resume_argv`로 이어 가며, herdr가 잃은 작업 공간은 판이 되살린다(C3, P3). 셸 패널은 herdr가 되살리면 같은 노드로 남는다(I8).
- 빈 곳(P7에서 메운다): herdr가 되살리지 못한 판이 띄운 셸, 판에 올린 에이전트(이어 가지 않고 셸이 되거나 빠짐), Claude Code가 아닌 종류의 대화 이어 가기, 끊긴 세션의 이름과 자리. 되살릴 수 있으면 같은 노드로 되살리고(셸은 같은 폴더의 새 셸, claude는 그 대화 ID로 이어 가기, 다른 종류는 herdr가 아는 이어 가기 정보가 있으면 그것으로), 못 하면 노드를 지우지 않고 "닫힘"으로 남긴다(J2).
- 실제 재부팅은 사람이 확인한다. 시험은 창·백엔드·herdr를 모두 끄고 다시 켜는 것과 강제 종료로 한다.

**J2. 닫힌 세션을 다시 연다**
- 판에서 끈 세션, herdr에서 사라진 세션, 패널이 닫힌 세션은 판(캔버스)에서 빠지지만 판 기록에 "닫힘"으로 남는다(지금도 `sessions.closed_at`이 남는다). 닫힌 세션은 사이드바의 그 워크스페이스 아래에 보인다.
- "판으로 열기": claude는 같은 세션 ID로 이어 간다(`--resume <ID>`, 판의 실행 인자, 새 설정 파일과 hook 토큰). 셸은 같은 폴더에 새 셸을 띄운다. 다른 종류는 그 하네스의 이어 가기를 쓸 수 있으면 쓰고, 아니면 같은 폴더에 새로 띄운다. 이름이 비어 있으면 같은 이름, 마지막 자리가 비어 있으면 그 자리에 놓는다. 그룹·연결은 되살리지 않는다(기록만 남아 있다).
- 닫힌 세션 목록에서 지우기(목록에서만 빼기, 대화 기록 파일은 그대로)도 둔다.

**J3. 열린 워크스페이스의 판 밖 Claude Code 대화**
- 판에 열린 워크스페이스(세션이 없어도 "+ 리포 열기"로 연 것 포함)마다, 그 리포의 지난 Claude Code 대화를 모두 찾는다. 대화 기록은 `~/.claude/projects/<폴더 이름>/<세션 ID>.jsonl`이고 터미널의 CLI와 데스크톱 앱이 같은 곳에 쓴다(`docs/research/data-sources.md`).
- 리포에 속하는지는 대화 기록 안의 `cwd`를 워크스페이스 키 규칙(4절 G1: git 공통 폴더, 워크트리 포함, git이 아니면 그 폴더)으로 풀어 맞춘다. 폴더 이름(경로를 바꾼 이름)은 되돌릴 수 없으므로 쓰지 않는다.
- 대화마다 보일 것: 제목(Claude Code가 남긴 요약이나 이름이 있으면 그것, 없으면 첫 사용자 지시 앞부분), 마지막 활동 시각, 마지막 지시와 답 앞부분, 폴더(워크트리면 브랜치), 판 세션인지(판 세션이면 그 노드로 이어진다), 다른 곳에 묶여 있으면 어디인지(J4).
- 파일이 많다(7일에 452개). 파일마다 머리 몇 줄과 꼬리만 읽고, 경로·크기·수정 시각으로 저장소에 캐시한다. 워크스페이스를 열 때와 주기적으로(또는 폴더 감시로) 새로 읽는다. 대화 기록은 읽기만 한다.
- 시험용으로 대화 기록 폴더를 바꾸는 환경 변수를 둔다(예: `MTASK_CLAUDE_PROJECTS`). 단위 시험은 고정 자료를 쓴다.

**J4. 묶여 있지 않은 대화만 이어 간다(갈라 열기 없음)**
- 판 밖 대화마다 다른 곳에 묶여 있는지 정한다. 묶여 있음: 데스크톱 앱의 대화(앱이 그 대화를 들고 있으므로 지금 돌지 않아도 묶인 것으로 본다), 지금 다른 터미널의 `claude` 프로세스가 열고 있는 대화. 묶여 있지 않음: 터미널에서 열었다가 끝난 대화.
- 묶여 있지 않은 대화를 "판으로 열기"하면 그 워크스페이스 영역에 판 세션을 띄워 같은 대화 ID로 이어 간다(`claude --resume <ID>`, 판의 실행 인자). 그 뒤로는 판 세션과 같다(hook, 이어 가기 등록, 연결). 이미 판 세션인 대화는 그 노드로 갈 뿐 새로 띄우지 않는다.
- 묶여 있는 대화는 가져오지 않는다. 목록에 어디에 묶여 있는지("데스크톱 앱", "터미널 · pid n")만 표시하고 "판으로 열기"를 막는다. 묶임이 풀리면(터미널의 claude가 끝나면) 열 수 있게 된다.
- **갈라 열기(`--fork-session`)는 하지 않는다.** 대화가 저절로 불어나는 것을 사용자가 원하지 않는다(2026-10-31). 판은 대화 ID를 새로 만들지 않고 늘 있던 대화를 이어 간다.
- 묶여 있는지 알아내는 방법은 P7에서 후보(대화 기록 안의 출처 표시, 데스크톱 앱의 세션 목록 읽기, `claude` 프로세스 명령줄, Claude Code가 남기는 세션 파일, 대화 기록 수정 시각)를 비교해 정한다. 확실하지 않으면 묶여 있다고 보고 열지 않는다(표시는 "묶여 있을 수 있음").
- 신뢰 대화상자가 뜨면 지금처럼 "터미널에서 답하기"다.

**J5. 사이드바**
- 왼쪽에 둔다. 평소에는 닫혀 있고, 위쪽 줄 왼쪽 단추와 단축키로 연다. 연 상태는 창이 기억한다. 캔버스는 사이드바 옆으로 줄어들 뿐 자리와 배율은 그대로다.
- 열린 워크스페이스마다 접히는 묶음(이름, ⎇/▢, 세는 값). 그 아래 순서: 판 세션(상태 필, 내 차례 질문 한 줄), 닫힌 세션, 판 밖 대화. 마지막 활동 순. 많으면 최근 몇 개와 "더 보기".
- 판 세션을 누르면 캔버스에서 그 노드로(H4처럼 들어가기), 리포 이름을 누르면 그 영역으로. 닫힌 세션과 묶여 있지 않은 판 밖 대화는 "판으로 열기"(J2·J4). 다른 곳에 묶인 대화는 흐리게, 묶인 곳 표시와 함께 두고 열 수 없다.
- 위에 거르기 칸(이름, 제목, 지시 글). 워크스페이스 묶음의 접힘 상태도 기억한다.

**만들며 정한 것(P7).** API와 세부는 `docs/P7.md` 1·4·5절이다.
- J1: "herdr가 다시 떴는가"는 백엔드가 도는 동안 herdr 연결이 끊긴 적이 있거나 백엔드가 꺼진 동안 herdr 서버 PID가 바뀐 것으로 본다. 그럴 때만 되살린다. herdr가 그대로인데 패널이 없어지면 사람이 판 밖에서 닫은 것으로 보고 닫힘으로 남긴다. 되살리기: 판이 띄운 claude는 그대로(한 턴도 안 돈 세션이 herdr 재시작 뒤 30초 안에 끝나면 같은 `--session-id`로 새로 띄운다), 판에 올린 claude는 15초 기다려 herdr가 이어 가지 않으면 herdr가 아는 대화 ID로 이어 가고(패널을 잃었으면 새 작업 공간), 셸은 패널을 잃으면 같은 폴더의 새 셸, 다른 종류(codex)는 herdr가 이어 가지 않으면 닫힘으로 남기고 빈 패널을 닫는다. 모두 같은 노드, 같은 자리, 덩어리·그룹·연결 그대로.
- J2: 닫힌 까닭(`killed`, `pane gone`, `pane exited`, `not resumed after herdr restart` 등)을 남긴다. 다시 열면 같은 이름(쓰이면 `-2`)과 마지막 자리(비어 있으면). 그룹·연결·덩어리는 되살리지 않는다. 판에 올린 claude를 다시 열면 그 대화 ID를 세션 ID로 하는 새 판 세션 행을 만들고 옛 행에 `reopened_as`를 남긴다(판 세션은 세션 ID가 대화 ID라야 hook·이어 가기가 맞는다).
- J3: 대화 기록은 머리 128KB와 꼬리(답이 나올 때까지 최대 1MB)만 읽고 경로·크기·수정 시각으로 캐시한다(표 `convo_index`). 글(제목·지시·답)은 열린 워크스페이스의 대화만 저장한다. 15초마다 바뀐 파일만 다시 읽는다. 실제 398개(4.8GB) 머리·꼬리 읽기 0.43초. 지시가 없는 대화 기록은 빼고, 판이 아는 대화는 판 밖 목록에 넣지 않는다. git이 아닌 폴더 워크스페이스는 다른 저장소가 아닌 하위 폴더의 대화도 담는다. 창에는 워크스페이스마다 칸별 300개까지 보낸다. 대화 기록 폴더는 `MTASK_CLAUDE_PROJECTS`(목록에만, `;`로 여럿)로 바꾼다.
- J4: 묶임 판정 순서는 (1) Claude Code의 세션 파일(`~/.claude/sessions/<pid>.json`)의 살아 있는 pid, (2) `claude` 명령줄의 대화 ID, (3) 데스크톱 앱 세션 목록(보관한 것도 묶임), (4) 대화 기록 안의 출처(`entrypoint`에 데스크톱), (5) 출처가 없거나 `cli`가 아님 → "묶여 있을 수 있음", (6) 30초 안에 쓰임 → "묶여 있을 수 있음 · 방금 기록됨", (7) 나머지는 묶여 있지 않음. 열기 직전에 한 번 더 판정한다. 실제 대화 398개 중 데스크톱 묶임 273개, 터미널 10개, 묶여 있을 수 있음 24개, 묶여 있지 않음 91개(2026-10-31). 세션 파일과 데스크톱 목록은 공개된 형식이 아니라 바뀔 수 있다. 갈라 열기는 하지 않으며 시험에서도 새 대화 ID가 생기지 않았다.
- J5: 단축키는 `Ctrl+Shift+E`(`Ctrl+B`는 Claude Code와 셸이 쓴다). 폭 340px, 칸마다 5개와 "더 보기". 상태는 창 프로필의 `localStorage`에 둔다.
- 단계: P7(끝남)

### K. 가지 펼치기(2026-10-31 추가, P8)

사용자 요청: 세션 하나에게 "워커를 불러", "어디에 하위 세션을 띄워"라고 지시하면, 그 세션이 하위 세션을 띄우고 herdr로 잇기까지 알아서 한다. 사람이 하나하나 띄우고 잇지 않는다. 지시하면 정해진 방법대로 가지처럼 펼쳐진다. 마크다운 뷰어 같은 화면 기능은 더 넣지 않는다.

지금(P4 F3)은 에이전트가 herdr로 직접 패널을 나눠 에이전트를 띄우면 판이 그것을 올린다(판에 올린 에이전트). 그 하위 세션은 판의 hook, herdr 스킬, 권한 모드를 받지 못해 상태가 거칠고 스스로 다시 펼치지 못한다. 에이전트가 명령을 직접 조합해야 하고 명령마다 승인을 묻는다. K는 이것을 판이 만드는 정식 하위 세션으로 바꾼다. 판에 올리기(F3)는 판 밖 방법으로 띄운 것을 위해 그대로 둔다.

**K1. 판의 명령으로 하위 세션 만들기**
- 판이 띄운 세션은 판의 명령 하나로 하위 세션을 만든다(예: `mtask child <이름> [--prompt "첫 지시"] [--role 워커] [--cwd 폴더] [--worktree 이름] [--model 모델]`). 하위 세션의 목록과 끄기도 같은 명령 묶음이다(`mtask children`, `mtask child-kill <이름>`).
- 백엔드는 부르는 세션을 부모로 알아본다. 판은 세션을 띄울 때 그 세션의 ID, 세션 토큰(판 API 토큰과 세션 ID의 HMAC), 판을 찾아갈 값(프로필, herdr 세션, 포트, 데이터 폴더)을 세션 설정 파일의 `env`로 넘긴다(작업 공간 env는 herdr 재시작 뒤 되살아나지 않는다, E7). 명령은 판 플러그인의 `bin/mtask`다(Claude Code가 플러그인 `bin/`을 Bash 도구 PATH에 올린다). 명령은 판 API 토큰을 쓰지 않고 세션 토큰으로 `POST /branch/child|children|kill`만 부른다. 사용자의 PATH와 설정 파일은 고치지 않는다. 같은 사용자 계정이라 격리는 아니다(`docs/P8.md` 4절).
- 하위 세션은 판이 띄운 정식 세션이다: hook, herdr 스킬 플러그인, 짧은 안내, 권한 모드, herdr 이름, 이어 가기 등록(B3). 기본으로 부모의 폴더, 모델, 노력 수준, 권한 모드, 그룹을 물려받는다. 지시에 다른 값이 있으면 그것을 쓴다. 그룹을 물려받으므로 그룹 동시 실행 상한(기본 4)을 지킨다.
- 부모와 역할 선으로 잇는다(역할 기본 "워커"). 하위 세션의 herdr 이름, 패널, 역할, 일 시키기·답 읽기 명령은 명령의 응답으로 부모에게 간다. 응답이 닿지 않았을 때만 F2처럼 대기열로 알린다(알림 턴이 더 돌지 않게). `mtask child`는 하위 세션이 준비될 때까지(최대 75초) 기다린다. 첫 지시가 있으면 ready 뒤 B1 규칙으로 보낸다.
- 다른 곳에 띄우기: `--cwd`가 다른 저장소나 폴더면 그 워크스페이스에 띄우고 선으로 잇는다. `--worktree`면 하위 claude를 `claude -w <이름>`으로 띄워 Claude Code가 자기 규칙으로 워크트리를 만든다(판은 워크트리를 만들지 않는다, BRIEF 2절). 신뢰하지 않은 저장소에서는 Claude Code가 `-w`를 거부하므로 판이 미리 `needs_trust`로 거부한다. 노드에는 F4처럼 워크트리와 브랜치가 보인다. 그룹은 같은 워크스페이스일 때만 물려받는다.
- Claude Code가 아닌 종류(`--kind codex`)도 띄울 수 있다. hook이 없으므로 F5처럼 다룬다.

**K2. 나무처럼 다시 펼치기와 스킬**
- 하위 세션도 같은 명령을 쓸 수 있다. 그래서 지시 한 번에 여러 단계로 펼쳐진다.
- 판이 넘기는 플러그인에 일 맡기기 스킬을 더한다(herdr 스킬 옆). 순서: 하위 세션 만들기 → herdr로 일 시키기(`herdr agent prompt <이름> "…" --wait`) → 답 읽기 → 모아서 보고. 끝난 하위 세션은 기본으로 두고(나무와 결과를 사람이 보게), 사람이 끄라고 하면 자기가 만든 하위 세션만 끈다. 짧은 안내(`--append-system-prompt-file`)에도 이 명령과 스킬을 한 줄로 알린다.
- 판이 띄운 세션의 설정 파일에 이 명령과 `herdr agent prompt|wait|read`의 승인 규칙을 넣어 묻지 않고 돌게 한다. 다른 `mtask` 명령(다른 세션 끄기 등)과 다른 herdr 명령은 넣지 않는다(지금처럼 승인 카드로 묻는다). herdr 명령은 대상을 가리지 않으므로, 판이 띄운 세션은 같은 판의 어느 에이전트에게도 묻지 않고 지시를 보낼 수 있다(8절).

**K3. 불어나지 않게**
- 상한: 세션 하나의 하위 세션 4개, 깊이 3단계(사람이 띄운 세션이 1단계), 판 전체에서 하위 세션 16개. 넘으면 만들지 않고 까닭(`too_many_children`, `too_deep`, `board_full`)을 명령의 응답(부모가 읽는다), 판 이벤트, 창 알림으로 남긴다. 상한은 설정(`branchMaxChildren`, `branchMaxDepth`, `branchMaxTotal`)이고 ⚙에서 바꾼다.
- 에이전트는 자기가 만든 하위 세션(자손 포함)만 끌 수 있고, 끄면 그 아래 자손까지 깊은 것부터 끈다. 다른 세션은 `not_parent`로 거부한다.
- 하위 세션은 같은 대화를 갈라 열지 않는다(새 세션 ID로 새로 띄운다).

**K4. 가지 모양으로 보이기**
- 하위 세션은 작게(480×300) 부모 오른쪽 열(사이 200)의 빈자리에 놓이고, 형제는 위아래로 쌓인다(4절 H7의 나무 배치를 새 노드 하나에 적용). 다른 워크스페이스에 띄운 하위 세션은 그 영역에 놓이고 선으로 잇는다. 사람이 옮긴 자리는 지킨다(새 노드를 놓을 때만 정한다).
- 노드 머리줄에 부모와 깊이를 짧게 보인다(예: "@lead의 워커"). 사이드바와 미션 맵에서도 부모 아래에 들여 보인다.
- 다시 켜도(4절 J1) 부모·자식 관계와 역할 선이 남는다.
- 단계: P8(끝남, `docs/P8.md`)

| 가지 펼치기 | 판이 띄운 세션은 판의 명령 하나(`mtask child`)로 하위 세션을 만든다. 하위 세션은 판이 띄운 정식 세션이다(hook, herdr 스킬, 권한 모드, herdr 이름). 부모와 역할 선으로 이어지고 부모에게 이름과 역할이 알려지며, 부모 오른쪽에 놓인다. 하위 세션도 같은 명령을 쓸 수 있어 지시 한 번에 나무처럼 펼쳐진다. 일 맡기는 순서(만들기 → herdr로 시키기 → 답 모으기)는 판이 함께 주는 스킬에 있다. 명령은 판 플러그인의 `bin/mtask`이고, 세션 설정 파일의 env에 든 세션 토큰으로 하위 세션 만들기·목록·끄기만 부른다(판 API 토큰은 쓰지 않는다). 이 명령과 `herdr agent prompt|wait|read`는 판이 띄운 세션에서 묻지 않고 돈다. 같은 사용자 계정이라 격리는 아니고, herdr 일 시키기는 같은 판의 어느 에이전트에게나 묻지 않고 간다(P8). 불어나지 않게 세션 하나의 하위 세션 4개, 깊이 3단계, 판 전체 16개까지만 만들고, 에이전트는 자기가 만든 하위 세션만 끈다. 하위 세션은 부모의 모델, 권한 모드, 그룹을 물려받는다. 지시에 폴더나 워크트리가 있으면 그곳에 띄운다(워크트리는 Claude Code의 `claude -w`)(2026-10-31 사용자 요청, P8). | 사람이 하위 세션을 하나하나 띄우고 잇지 않고, 지시만 하면 세션이 알아서 펼쳐지기를 원한다(사용자). 에이전트가 herdr로 직접 띄운 세션(아래 "판에 올린 에이전트")은 판의 설정을 받지 못해 한 단계에서 멈추고, 명령을 매번 조합하고 승인해야 했다. |

P5의 워크스페이스별 판을 대신한다). | 탭과 목록은 한 번에 하나만 크게 보여서 무엇이 돌고 있는지 숨긴다(Orca, Ovis 방식). 워크스페이스별 판도 같은 문제가 있다. 세부는 `docs/PLAN.md` 4절 H와 9절 |

| 상태 수집 | herdr 상태(working, blocked, idle, done)를 패널 상태의 기준으로 쓴다. 질문과 권한 상세, 마지막 답, 오류는 Claude Code의 `type: "http"` hook으로 받는다. hook은 세션마다 설정 파일을 만들어 `--settings`로 넘긴다. hook 토큰은 그 파일 안에 값으로 쓰고, 파일은 세션이 판에 있는 동안 지우지 않는다(2026-10-29, E7 결과로 바꿈). | herdr는 무엇을 묻는지와 오류를 주지 않고, http hook은 SessionStart에서 오지 않는다(E2). 그래서 둘을 합친다. herdr가 세션을 이어 갈 때 설정 파일을 다시 읽고, 작업 공간 `env`로 넘긴 토큰은 되살리지 않는다(E7). 사용자의 `~/.claude/settings.json`은 건드리지 않는다(symvibe는 이 파일을 고친다). http hook은 프로세스를 띄우지 않는다. command hook을 PowerShell로 돌리면 이벤트마다 약 0.2초가 걸린다. |

**v0.7(P8)에서 한 것:** 가지 펼치기(2026-10-31 사용자 요청, `docs/P8.md`). 판이 띄운 claude에게 "워커 둘을 만들어 X, Y를 시키고 모아 와"라고만 보내면 승인 없이 하위 세션을 만들고 herdr로 시켜 모아 보고한다. 하위 세션도 다시 펼쳐 3단계 나무가 되고, 상한과 남의 세션 끄기는 거부된다. 마크다운 뷰어 같은 화면 기능은 더 넣지 않는다(사용자). 신뢰한 저장소에서 워크트리로 띄우기는 사용자가 확인한다.

**그 뒤 후보:** 음성과 스튜디오는 맨 나중이다. 인계·포워드와 플래너는 에이전트가 herdr 스킬로 직접 하므로 판이 따로 만들지 않는다.

## 옮김: 옛 BRIEF 7절 열린 질문

아직 열린 것은 `docs/PLAN.md` "열린 결정"으로 합쳤다. 닫은 것은 위 "2026-10-31 열린 질문에서 닫은 것"에 있다.

- herdr의 화면 스트림(`terminal session observe/control`)은 공개 소켓 API가 아니라 CLI 보조 통로다. herdr를 업데이트할 때 바뀔 수 있어서 버전을 고정한다. 바뀌면 어댑터에서 흡수한다.
- 판이 띄우지 않은 에이전트(에이전트가 띄운 에이전트)와 Claude Code가 아닌 종류가 일을 시키면 판은 선을 긋지 못한다. hook이 없기 때문이다. 에이전트가 띄운 에이전트에 판의 설정(hook, 스킬, 권한 모드)을 물려줄지 정하지 않았다(P4).
- 명령 바에서 보낸 긴 지시(4줄 이상이나 800자 초과)는 Claude Code가 붙여 넣은 자료(`<pasted_content>`)로 감싸 모델에 넘긴다(E3). E3와 P1(5줄 지시)에서는 모델이 그 안의 지시를 따랐다. 실제로 쓰면서 계속 본다.
- 리포지토리 하나를 워크스페이스 하나로 정했다(3절, P5). 워크스페이스 안의 그룹(halo)을 "작업"과 같은 것으로 볼지는 아직 정하지 않았다.
- 관계를 언제 선으로, 언제 붙여 묶기로 보일지 정하지 않았다. P6은 herdr에서 실제로 나뉜 패널만 처음부터 붙이고 나머지는 선으로 두며, 사람이 직접 붙이고 뗄 수 있게 했다. P6a 작업자는 써 보고 "나뉜 패널은 늘 붙이고, 서로만 주고받는 쌍은 붙이기를 제안만 하고, 역할·시킴·띄움은 선으로"를 제안했다(`docs/P6a.md` 5절). 사용자 원문 중 이 대목 근처의 한 문장("그리고 항상 이렇게 아플까?")은 음성 인식이 불분명해 열어 둔다(2026-10-30).
- 판 밖 대화의 묶임 판정은 P7에서 정했다(3절 "세션 되찾기"). 세션 파일과 데스크톱 앱 세션 목록은 공개된 형식이 아니라 Claude Code나 앱이 바뀌면 읽지 못할 수 있다. 그때는 대화 기록 안의 출처와 수정 시각만 남는다.
- 가지 펼치기(P8)에서 일이 끝난 하위 세션을 부모가 끌지, 사람이 볼 때까지 둘지. 기본은 둔다(나무 모양과 결과를 사람이 보게). 상한(하위 4, 깊이 3, 전체 16)이 맞는지는 써 보고 정한다.
- 판 밖 대화를 판으로 열 때 원래 대화의 모델을 따를지, codex 같은 다른 종류를 herdr 재시작 뒤 판이 직접 이어 갈지 정하지 않았다(P7).
- 명령을 여러 콘솔에 나누는 플래너는 symvibe에서 유료 외부 서비스다. multitask에서는 사용자 구독의 `claude -p`(헤드리스 실행)로 돌리는 것을 제안한다.
- 창을 닫으면 앱이 끝나 OS 알림도 오지 않는다. 창 없이 알림을 받으려면 트레이 상주가 필요하다(P3). P6에서 설정으로 켜는 트레이 상주를 만들었다(기본 꺼짐). 기본값은 써 보고 정한다.
- aside(브라우저 에이전트)의 기록을 판에 붙일지, 언제 붙일지 정하지 않았다. 읽는 방법은 `docs/research/data-sources.md`에 있다.

## 2026-10-31 데스크톱 앱 세션을 판에 얹는 안(하지 않음)

사용자가 Claude Code 데스크톱 앱과 판을 함께 쓰는 길을 물었다. 조사한 것(최근 3일 대화 기록, 수만 셈): 데스크톱 앱도 `~/.claude/projects`에 같은 형식으로 쓴다(213개 중 81개). 서브 에이전트는 세션 폴더의 `subagents/`(55개 세션, 288개), 백그라운드 작업은 `run_in_background` 호출(585)과 `task-notification`(1,855)으로 남는다. 그래서 데스크톱 세션을 판 위에 읽기 전용 노드로 얹고(대화 보기, 서브 에이전트·백그라운드 작업 하위 노드, 사이드 세션 선, "앱에서 열기") 상태는 추정으로 보이는 것은 가능했다. 판에서 데스크톱 세션으로 입력하는 공식 통로는 없고, 창에 키를 보내는 우회는 위험해서 권하지 않았다. 정확한 상태는 `~/.claude/settings.json`에 hook을 걸어야 해서 지금 규칙과 맞지 않았다.

사용자는 데스크톱 앱 인식을 빼는 기조를 지키고, 판의 CLI 사용성을 먼저 끌어올린 뒤 데스크톱 앱의 대화를 판으로 한 번 옮겨 오는 기능을 나중에 만들기로 했다.

바꾸기 전의 BRIEF "데스크톱 앱" 행: "진행 중인 작업 때문에 당분간 앱을 계속 쓴다. 판은 앱 세션을 보여주지 않는다. P3에서 만든 읽기 전용 카드는 P4에서 뺐다(2026-10-30)."

## 2026-11-02 워크트리 영역

사용자는 작업자들이 워크트리에서 일하므로, 지워지지 않은 워크트리의 세션과 대화를 본 저장소 묶음에서 브랜치로 갈라져 나간 묶음으로 보이고 화살표로 잇기를 바랐다. 워크스페이스 키는 그대로 리포 하나로 두고, 워크트리는 그 하위 영역으로 한다. BRIEF "워크스페이스" 행의 이전 문장은 다음과 같다.

> 키는 시작 폴더의 git 공통 폴더(`--git-common-dir`)라서 워크트리는 본 저장소와 같고, git이 아닌 폴더는 그 폴더다.

## 2026-11-02 macOS 포팅

기존 구현은 Windows 파이프·PowerShell·AppData 경로를 전제로 했다. 사용자 요청으로 macOS Unix 소켓·POSIX 프로세스 조회·Application Support 경로를 추가한다. herdr는 0.9.5와 프로토콜 22를 유지한다. 코드 및 라이선스가 다른 symvibe의 자산은 가져오지 않는다.
